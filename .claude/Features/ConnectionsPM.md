## Connections


A **Connection** is a link from one Page to another, written in the page's Markdown body or inside a Text property's value. Two syntaxes spell one — the wikilink `[[Name]]` and the Markdown link `[Alias](Name)`, where a name is a page's title or any tail of its Nexus path, `Folder/Title` — and the word covers both. A connection may also be held as the whole value of a Link property, where it reads as a connection rather than an address. Connections are the only page-to-page relation Pommora has; Contexts are the relation layer, and there is no relation-type property. 

### Syntax + Scope

The grammar lives in `Core/Connections/connections.ts` (the wikilink) and `Core/Connections/links.ts` (the markdown link), shared code both processes read, and one walk over both syntaxes reads every link for the editor's tokenizer, the content index, and main's rename rewriter alike. One normalization — trim, case-fold, NFC — is applied to every title and every fragment on every side, so the scanner, the resolver, and the uniqueness check always agree. A written name also drops a trailing `.md`, and the one key every side reads is that folded, extension-less name.

- **Wikilinks** — `[[Title]]` resolves by its title and `[[Folder/Title]]` by the tail of its path; Pommora writes the path form only where a title is shared, with the title as its alias where the link carries no heading and isn't an embed, as Obsidian does. `[[Title#Heading]]` names a heading inside that page, and `[[#Heading]]` names a heading on the page it sits in; the fragment after the `#` is the heading's own text. `[[Title|Alias]]` shows the alias and still resolves by the title; the title and its pipe join the hidden markers and reveal with the caret like any other syntax, and an alias follows a fragment the same way. A title can't contain `|`, `#`, or `§`, and the name rule rejects them at creation; a `§` typed where a title is being written becomes `#`, so the file only ever holds `#`.
- **Markdown links** — `[Label](Title)` names a page through its target, percent-encoded so spaces and parentheses survive, and `[Label](Title#Heading)` and `[Label](#Heading)` carry the same fragments the wikilink does; a `§` typed in the target before its fragment becomes `#` the same way. A target whose page half carries a scheme addresses something outside the Nexus and is never read as a page name; one holding `/` and no scheme is a path to a page.
- **Embedded Pages** — in-page embedded links using variations of `!` syntax aren’t considered matrix-like connections between pages; however, they *are* included within the same framework. Connections using `!`-prefixed form standing alone on its own line in a page body renders as a live tile — `![[Title]]` a page embed and `![Label](url)` a webpage embed — anywhere else when no embed is formed, it reads as a `!` followed by a connection or a link.

### Resolution

Every name the scanner finds is looked up in the page index, an in-memory map both processes build from the one entity list the page tree projects (`Core/Nexus/record.ts`), and lands in one of these states, a heading half reading against its page's headings and muted when none matches:

- **Resolved** — the name is a page's full path, or exactly one Page's path ends with it. The link is styled and navigable, and its target's id is known in memory.
- **Ambiguous** — more than one Page's path ends with it, so no target can be chosen. The link is muted and inert until one side is renamed or the link gains a longer path.
- **Phantom** — no Page holds it. The link stays literal bracketed text and goes live on the editor's next update once a single match exists. A click on a link that doesn't resolve seats the caret in its name, in the editor, a resting cell, and a one-line value's field alike, so the one gesture that can fix it is the one offered.

Main holds the same index for its own decisions, what each written name resolves to before and after a change, and resolves no link for display. Where it reads one without the index, as the Paste As rows do, a target carrying no scheme names a page.

### The Rename Cascade

A connection resolves by its written name, so renaming or moving a page, or renaming or moving a folder its path runs through, rewrites every link that resolved to the page before so it resolves to it after, by one rule: a link whose tail is unchanged is left as written, one whose tail changed takes the page's new name at the depth it was written, one differing from that name by its `.md` alone is left as written, and a bare link whose title comes to be shared gains the full path. A page created, renamed, or restored onto a title another page holds re-spells that page's bare links the same way. `Core/Connections/rewrite.ts` is the primitive — span edits over the one walk of both syntaxes, embeds included, with Link and Text property values riding the same rewrite as the body — and the cascade runs it over every file the content index relates to the page's names (its frontmatter values only under keys the registry types as Link or Text, or leaves untyped), every markdown tile, the Spaces whose values under those keys name it, and, for a page, the values a property Remove cached, confirming each under its own lock, and an alias or label that only showed the renamed title or heading follows it; Connections inside code syntax aren't cascaded. A File property's `[[Basename.ext]]` values are in a different domain and are left alone. Anything inside a code span or fence is a sample and is never rewritten. A rename or move made outside Pommora is paired by the page's ID at the next settle, whichever order its two file events arrived and however many batches apart, or at the next open for one made while the app was closed, and takes the same rewrite, logged rather than noticed.

Renaming a heading carries its links once the rename settles — when the caret leaves the heading line, the editor loses focus, or the page closes — on its own page, in every file the index names under the page's own names, and in every markdown tile that links one, from the old text to the final one in one pass. A rename made outside Pommora takes the same path once the content index reads it, whether it lands while the app watches, during the catch-up after the watcher starts, or while the app was closed, when the next open carries it. Where a heading with the old text still stands, or the new text matches another heading, no link moves, and links to the old text read as missing. A heading rename on one of two same-titled pages moves only the links that resolve to that page.

Deleting a page strips the Link property values naming it from every page and Space the tree and both stores hold, outside the delete, through the same sweep, and the delete's notice counts the pages and Spaces outside both stores it reached. Bodies and Text values keep their connections and read as phantoms. A restore from the Trash returns each value to the page or Space it came from while **Restore Links On Deletion** is on. A delete strips a value only where its name resolves to nothing afterwards, so a name another page still answers is left to that page. A restore re-spells the live links that named its old path or that its arrival makes shared, and refills the stripped values to the page each named, by identity; **Restore Links On Deletion** governs the refill alone.

### Rendering

A connection renders as inline text in the connection color (the **Internal Link Color** setting), never as a chip, with its brackets hidden until the caret enters it. Revealed, an aliased connection shows both halves — the target marked as a target, the alias as prose — with a link glyph between them that takes the connection color when the target resolves and reads muted when it doesn't. A connection being typed, in either syntax, wears the color from the first character typed into it until the caret leaves the whole link, so it never reads as prose while it is being written. A markdown link that names a page uses the same color, leads to the same place, and shows the same glance pane; one that names a website keeps the external-link treatment (External Link Color); and one that names neither reads as an unresolved connection does. A connection naming a heading reads per **Heading Link Style** — `Page § Heading`, or `§Heading` alone — a link to a heading on its own page reading as the heading alone, and an alias overriding both halves. A heading its page lacks reads muted, and so does the alias or label standing in for it.

Clicking a connection, a Link property's value included, opens the page, routed by **Open Connections In Preview** — the Page Window when the setting is on, otherwise wherever **Open In Preview** sends the page, and a new tab on ⌘-click. Resting on a resolved connection raises the glance pane with a read-only render of the target. Ambiguous links keep the bracket treatment in a muted tone; a phantom is inert and reads either muted with its syntax showing or as plain prose, per **Display Unresolved Links As Plain Syntax**, on every surface a link draws in. A connection naming a heading opens its page and travels to the heading, folds opened, the glance pane opening scrolled there; a link to its own page's heading travels in place — from prose, a table cell, or a footnote — with no glance and no menu, while a bare `§Heading` run in a Text value under Automatic *§In-Page Heading Resolution*, in its pane or at rest in a view cell, answers for the page holding the value: it glances, and its menu offers the opens and the copies. Where a heading text repeats, the nearest one answers.

### The Link Menu

Right-clicking a resolved link, wherever it sits, opens one native menu built from one model (`Core/Actions/connectionMenu.ts`). The rows follow what the link is and where it sits:

| Action | Connection | External Link |
| --- | --- | --- |
| **Open** | Preview · New Tab (reads *Open*, and leads, where the page already holds a tab; each dropped where its own surface is already showing the page, unless the link names a heading) | Preview · Open In Browser (the in-app browser, offered for a web address, and the system one) |
| **Author** (editable surfaces) | Edit Title · Edit Link | Edit Title · Edit Link |
| **Copy** | Copy Link · Copy Path | Copy Link |
| **Format** (editors) | — | Format ▸ Full Link · Short Link · Page Title (for a web address), rewriting the label alone |
| **Close, in an editor** | Remove Link (keeps the shown text as prose) · Delete | Remove Link (keeps the label as prose) · Delete |
| **Close, on a property value** | Clear (· Remove on a card and in the Panel, hiding the property there) | Clear (· Remove) |

Edit Title edits the shown text, adding one where there is none, and Edit Link edits what the link points to. The editors are a page body, a table cell live or at rest, a Text value's pane, and the one-line field a Link value or a single-line Text value is typed in; a Link value's look follows its property's Format instead. Copy Link on a connection naming a heading copies the whole fragment form. An embedded page at rest offers the opens and the copies; a glance pane and a page's history offer no link menu. A phantom, ambiguous, or invalid link offers no link menu, and the right-click falls through to the editor's own menu where there is one. Inside a link's own syntax the menu stands down, leaving the native editor menu its spelling and substitution items.

### Autocomplete

One picker (`Core/MarkdownPM/Autocomplete/autocomplete.ts`, driven by `useConnectionAutocomplete`) serves every place a connection is typed — the page editor, table cells, markdown block tiles, a Text value's pane, and the one-line field a Link value or a single-line Text value is typed in — anchored below the caret and flipping above only to stay in the viewport. Typing `[[` or `[label](` opens it whether or not Pair Brackets is on, and an unclosed link reads as the link it will be once closed. Arrows move the selection, Return or a pick completes the link, writing its closer where it isn't written yet and resting the caret past it, Escape closes and leaves the typed text, and each key falls through to the editor while the panel is closed. The pane shows as many suggestions as its height allows and scrolls to the rest, carrying the selection with it as the arrows move past the last visible row. Its free edges resize it, and the size is remembered per machine; its width fits its titles until it's resized itself. A page row names its location beneath its title — the containers it sits in, drawn from the same ancestry every trail in the app reads. The alias list slides in only when a pick opens its slot, which keeps the panel open: the suggestions push aside on the shared `FrameSlide` and the remembered aliases take their place, so the two lists read as one surface rather than two openings. What it offers depends on where the caret is:

- **Inside `[[ ]]`** — Pages nexus-wide, matched by the one search rule over their titles and their folders and ranked by score, a pick written as the page's name; the list closes once the typed name resolves, and an empty `[[` browses them alphabetically.
- **After a `#` or a `§` in a title or a markdown link's target** — the headings of the page that title names, read from the content index and nested by level; `[[#` and `](#` list the headings of the page being written in. Headings can also be assigned via the initial connection autocomplete panel via the sliding secondary panel accessed from clicking a hovered pages trailing chevron.
- **After a pipe, or in a markdown link's label** — the aliases the Page its target names has been given before, filtered by what's written there, a pick written into the label escaped and resting the caret past the link; with the list closed, Return in either rests the caret there rather than breaking the line. Accepting a page or a heading whose page has aliases to offer, in either syntax, opens the list without a keystroke when **Automatically Suggest Existing Aliases When Linking A Page** is on, and under the same setting Return in a markdown link's written destination moves the caret on to its label. Each row carries a × that deletes that alias, and an alias names no location of its own, so it wears no trail.
- **Inside a markdown link's `( )`** — Pages, matched by the target's page half; accepting one encodes the target, writes an empty label as the page's title, and rests the caret past the link. A heading accepted after the `#`, directly or through the chevron, is encoded the same way and fills an empty label with its own text, and a label emptied and left fills with that default — the heading, else the title — as an emptied alias drops its pipe and an emptied heading after a title its `#`; one the caret only passes through stays as written.

**Remove Title On Link Change** decides whether a re-aim — a pick, a paste over a link, or a pick inside a Link value's field — drops the alias or label the link was showing, in either syntax. The shown text drops only where the link, as it read before the edit began, pointed somewhere — a page, a heading of its own page, or an address — so a label or alias typed while the link is being written stays.

**Alias memory.** A Page remembers the aliases it has been given. The list is written where an alias is authored — a body link of either syntax, typed into or picked, that shows a page an alias or label it didn't before once the caret leaves it, or a Link property value that comes to show one — rather than derived by scanning bodies, and it is managed from one list: the body picker's alias stage and the page panel's Aliases row show the same rows. × or the row menu's Delete deletes an alias, a double-click or the row menu's Rename renames it in place, **+** adds one at the end, and in the body picker a single click inserts once the double-click window passes; link text is never rewritten. The order is the user's: a used alias keeps its place, a new one joins the end, and a drag in either list reorders it. An alias is one name whatever its case, the newest spelling standing; shown text that only names its target — the page's title or the heading, as written now or before the edit, as a retargeted link's kept label does — is never one, and a link naming a heading adds nothing, though the picker still offers the page's aliases in its shown slot. The host applies each edit to the stored list. It is keyed by page id, so it survives a rename, and lives in the page's metadata, so it travels with the Nexus — the alias itself is on the page in universal syntax, and losing the record costs a suggestion, never a link.

### In-Page Heading Resolution

**In-Page Heading Resolution** decides what reaches a heading on the page being written. Under Explicit, the default, link syntax does. Under Automatic, a bare `§Heading` in prose reaches one as well: the text after the `§` is read against the page's outline, and the longest heading it begins with is the target, provided the match ends at the run's end or at a non-word character. Typing a `§` in prose, or a `##` that becomes one, opens the heading list on the keystroke, in a table cell or a Text value listing the page it sits on, and picking a heading writes the bare text. The file keeps that text bare, so the page reads as prose in every other Markdown tool.

#### Known Issues

- **The cascade is per-file, not cross-file atomic.** A file it can't write keeps the old link while the rename stands, and the rename's warning counts the files left behind.

#### Prospects

- **Backlinks** — a surface listing every Page that links to the current one. The content index records each relationship with its kind — body link, citation, embed, or a link in a frontmatter value under its key — so the surface is a read over those rows; the surface doesn't exist.
- **Wider targets** — Tasks and Events, and block anchors (`#^`).
