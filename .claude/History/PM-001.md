### PM-001 — The Page Outline

**Dates:** 08-07-2026

#### Summary

A page carried no way to see its own shape. The heading folds had existed for some time, so the editor already knew where every heading sat, but nothing surfaced that knowledge, and moving through a long document meant scrolling it. The Outline closed that: a toolbar dropdown, present only while the detail pane holds a Page, listing the page's headings as a nested collapsible tree and travelling to whichever one is chosen.

The surface was assembled rather than built. `Toolbar/OutlineDropdown.tsx` took its placement, trigger, and dismissal from the pattern `ViewDropdown` and `SpaceDropdown` already followed, and its rows are the design system's `DisclosureRow` — a data-agnostic primitive that had been proven recursive by the grouping and filter panes. The one piece with no precedent was the nesting itself, which became `Toolbar/outlineTree.ts`: an iterative ancestor-stack pass attaching each heading to the nearest heading of a strictly smaller level, so a document that skips a level or opens at a depth below the first nests correctly rather than needing a branch per case. The dropdown occupies the Views button's slot rather than adding one, since a selection resolves to either a container or a Page and the two are never on screen together.

Deriving the outline reused the editor's own heading scan rather than adding a second reading of what counts as a heading. `MarkdownPM/editor/folding.ts` had one such scan inside `headingSections`, whose contract drops a heading with no body beneath it because there is nothing there to fold. An outline has the opposite obligation — omitting those would show only the second of two consecutive headings, and would lose a trailing heading entirely. The scan was extracted to a private `scanHeadings`, and `headingSections` and a new `headingOutline` were both built on it, so the fence-parity rule and the ordinal that distinguishes repeated heading text can never diverge between the chevrons and the list while the two functions keep their different drop rules.

**Travel:** Clicking a row leaves the document and the caret untouched but opens any collapsed section hiding the destination, on the reasoning that arriving at a heading whose body is still folded is indistinguishable from not having moved. `expandFoldsAt` was added beside the existing `toggleFoldAt` as a second position-addressed entry point into the fold state, opening a heading's own fold and each ancestor fold containing it. The travel then waits out the reveal before measuring, because a collapsed section has no height to scroll to. A heading arrives at the band the page header occupies — the value the editor already publishes as `--header-zone` and the body already pads itself by — which is the height a page's own inline title reads at, rather than pinned against the viewport's edge.

**The glide:** The jump was initially instant, matching every other scroll in the application. It became an animated travel, and since no animated scroll existed anywhere, the primitive was built in the design system rather than in the calling surface. `scrollGlide` joined `design-system/interactions/autoscroll.ts` as a second entry point, sharing that module's scroller resolution and its one-owner-at-a-time rule while deliberately sharing none of its motion: the drag loop is open-ended and takes its speed from the pointer's distance to a container edge, which is a different animation rather than a parameter of the same one. The beat is proportional to the distance and clamped at both ends, so near and far jumps move the document at one apparent speed. Two behaviours the drag loop never needed were added — any real scroll input cancels the travel, and reduced-motion arrives immediately.

The first version resolved the destination once and corrected with the editor's own `scrollIntoView` on arrival, which produced a visible jump at the end of an otherwise smooth move: CodeMirror estimates the height of blocks it has not rendered, so the destination computed up front sharpened as the travel revealed the real content, and the correction closed that gap in a single frame. The destination is now re-read every frame and the easing converges on it, which absorbs the drift into the motion and removes the correction entirely. The beat remains fixed from the opening distance, so a destination shifting underfoot changes where the travel lands but never how long it takes.

**Underneath:** Three shared mechanisms the Outline stood on were found wanting and corrected in place rather than worked around. Their defects had been latent because no previous consumer exercised them the way this one did.

#### Changes Made

- **`Toolbar/OutlineDropdown.tsx`:** The surface. An outer component gates on the selection resolving to a Page and delegates to an inner one holding the state, so leaving the page unmounts the dropdown rather than leaving it open with nothing to dismiss against. The pane mounts only while open, so a closed outline derives nothing, and it subscribes to the page body there rather than in the trigger.
- **`Toolbar/outlineTree.ts`:** `outlineTree` nests a flat, level-carrying heading list using an ancestor stack, attaching each heading to the nearest heading of a strictly smaller level. Iterative, single-pass, and bounded at six levels by the heading grammar itself.
- **`MarkdownPM/editor/folding.ts`:** `scanHeadings` was extracted as the single fence-aware heading scan. `headingOutline` was added on it, returning every heading with its offset, level, text, and ordinal-disambiguated key; `headingSections` keeps its own rule of dropping body-less headings. `expandFoldsAt` was added as a position-addressed opener matching a heading's own fold and every ancestor fold containing it.
- **`MarkdownPM/editor/decorations.ts`:** `sliceStartLine` was added, and the viewport tokenize now opens on the line it returns — forward past any fence whose interior or closer the slice would otherwise resume inside, and back to the line owning an indented run. `visibleInlineTokens` takes the whole-document scan in place of a fence range list. The guard that dropped tokens landing inside a fence was removed along with the condition that required it, and `DocScan.fencedRanges`, which existed only to feed that guard, came out with it.
- **`MarkdownPM/editor/docCache.ts`:** `docSpanTokens` joined the per-doc-version memo seam beside `docString`, `docScan`, and `docLineIntentsOf`, keyed additionally by the visible span set and holding one slot per version, since a scroll moves the span set forward rather than returning to the one it left.
- **`Detail/pageEditor.ts`:** `revealPageOffset` resolves the page's live editor, opens whatever hides the destination, and travels there. `headerZone` reads the editor's published `--header-zone` to seat the arriving heading where the inline title reads.
- **`design-system/interactions/autoscroll.ts`:** `scrollGlide`, `glideMs`, `easeOutQuint`, and `stopGlide` were added beside the drag loop. The destination accepts a thunk and is re-read per frame; the duration is distance-proportional and clamped; a drag claims the scroller from a travel in flight, and a travel yields to real scroll input.
- **`design-system/components/menu/DisclosureRow.tsx`:** `useDisclosureSet` gained a `defaultOpen` parameter and now stores the exceptions to it rather than the open identifiers, which gives a default-open tree without seeding and stays correct as nodes appear and vanish. Its `Reveal` gained `fill`.
- **`design-system/components/menu/menu.css.ts`:** The row's padding, gap, and twisty width became named constants, with `TITLE_X_TWISTY_ONLY` derived from them. The rail's column became `--menu-rail-x` with the previous value as its default, and the disclosed run's indent is now stated as a clearance past that column rather than as an independent number.
- **`store.ts`:** `openPageBody` was extracted as the single reading of the open page's current text, folding the live editing buffer over the load snapshot; the outgoing-tab capture keeps its own rule, which keys on the selection's path.
- **`design-system/symbols/index.tsx`:** `list-tree` was added to the curated registry as the Outline's glyph.
- **`Toolbar/toolbar.css` and `Toolbar/viewDropdown.css.ts`:** The toolbar's swallow transform moved off a positional `:first-child` selector onto the dropdown wrapper's own class, since which dropdown is present depends on the selection.

#### Issues Resolved

- **Inline syntax dropped out on a scrolled document:** Code spans, emphasis, and connections rendered as plain text while scrolling down, repainting roughly a screen-height into a scroll back up. The viewport tokenize reads a text slice, and a slice beginning inside a fenced code block reads that fence's closer as an opener, inverting the parity for every line below it — prose masked as code, and code parsed as prose. CodeMirror spends its render margin in the direction of travel, which parks the slice's opening line on the top edge of the screen while scrolling down and a full margin above it while scrolling up, accounting for both the direction of the fault and the distance at which it healed. Folded sections and table widgets split the visible ranges, so the same boundary could fall mid-screen with no scrolling at all. Opening the slice at a self-evident block boundary closed it. The guard written alongside the original viewport scoping had covered only tokens landing inside a real fence, never the ones a phantom fence suppressed.
- **Every caret move paid a Markdown parse:** The decoration rebuild triggers on a selection change and a focus flip as well as an edit and a scroll, because the markers a construct reveals depend on where the caret rests. The inline tokenize ran on each of those, so an arrow key re-parsed the visible span through mdast and its regex passes to arrive at tokens the caret cannot affect. The parse now answers to the document version and the span set, which leaves an edit and a moved viewport paying it and a caret move reading it back.
- **Emphasis lost on nested list lines:** A slice opening on an indented line read the indentation as an indented code block, which suppressed the emphasis the owning list line would have licensed. Regex-sourced tokens on the same line survived, so the loss presented as specific to bold and italic. The same boundary rule closed it.
- **Auto-pairing closed against a following word:** Typing any opener immediately before existing text inserted its closer into that text — `|word` and `(` produced `(|)word` — across brackets, parentheses, quotes, backticks, and both emphasis markers. The gate read only the character behind the caret and nothing ahead of it, so the rule was half-built rather than broken; mid-word it appeared to work for the gated markers only because the character behind was also a letter. A forward guard was added ahead of every branch.
- **The forward guard swallowed the underscore:** The guard's first form tested the following character against the word-character class, which matches `_` — the one closer that is itself a word character. Underscore lost its type-over and its doubled form could no longer promote. The construct's own closer is now exempt from the guard.
- **Nested disclosure rows never truncated:** `DisclosureRow` rendered its `Reveal` without `fill`, leaving the disclosed column at `max-content`, so a nowrap title widened the run instead of ellipsising within it. Only root-level rows truncated. The flag was added, which also corrects the grouping and filter panes.
- **The dropdown reappeared unbidden:** Returning `null` below the component's hooks left the open state alive with no wrapper for the dismiss handler to fire against, so leaving the page and returning to it re-presented the pane, with a stale resize listener holding a detached node that measured zero and uncapped the pane's width. The gate moved above the state.
- **The heading scan dropped headings an outline needs:** `headingSections` omits a heading with no body beneath it, which is correct for folding and wrong for an outline — two consecutive headings would have shown only the second. Separating `headingOutline` from the shared scan closed it before the surface shipped.
- **Travel stopped short of a collapsed heading:** A fold entry spans its heading's body rather than the heading line, so the opener matched ancestor folds but never the fold belonging to the clicked heading itself, which arrived still collapsed. The predicate now matches the heading's own entry as well.
- **A jump at the end of the travel:** The destination was resolved once against estimated block heights and reconciled on arrival, which placed a single-frame correction at the end of a smooth move. Re-reading the destination each frame converges the estimate into the easing and removed the correction.
- **The toolbar's shift aimed positionally:** A transform keyed on the right cluster's first child named whichever dropdown the current selection happened to render. It now keys on the shared wrapper class.
