### PM-005 — The JSON Write Primitive Takes Its Own Lock

**Dates:** 08-08-2026

#### Summary

`rmwJsonStrict` was the JSON counterpart of `rewritePageSerialized` — read fresh, merge, write atomically — differing from it in one respect: it took no lock, and its docstring named serialization as the caller's job. Seven callers assembled the missing half by hand and two never did. The primitive now wraps its own body in the per-file chain, keyed on the path it writes, so the lock is derived rather than passed and a second spelling of that key is not expressible.

The removal of the seven wrappers had to land in the same commit as the fold. The chain is not reentrant, and every one of the seven locked the same key its inner call passed, so any intermediate state would have deadlocked the tree rather than merely failing it. Each span was read whole beforehand to confirm two things: that the keys matched, and that no wrapper enclosed a second disk touch — each turned out to hold the read-modify-write plus pure computation, a `.catch` or a parse of the value already returned. `patchConfig` disappeared with them, its arms calling the primitive directly.

**What the fold cost, and what it did not.** The two writers of `.nexus/state.json` were left untouched and became covered anyway, which is the difference between moving a lock down a layer and adding one. The work carried no bug justification: the sequence originally offered for that file — two sidebar drags overlapping — cannot occur, because a drop is hundreds of milliseconds of physical motion against a single-digit-millisecond write, and each drop dispatches one operation. The arc was ratified on cohesion instead, and the record says so in order that no later session re-argues it as a defect.

**An import cycle the plan had not foreseen** surfaced on the first edit. `io/fileLock.ts` imported `atomicWriteFile` for `rewritePageSerialized`, so a primitive in `io/atomicWrite.ts` reaching for the lock would have made the two modules mutually dependent. Rather than accept a cycle that happens to resolve, `rewritePageSerialized` moved to sit beside the writers it uses; `io/fileLock.ts` now imports nothing at all, which is the arrow a lock primitive should have. Six modules were re-pointed and the compiler enumerated every one.

**The parallel mechanism went with it.** `.nexus/properties.json` had been guarded by a module-level promise chain while `.nexus/contexts.json` guarded the identical operation with the shared per-path lock, and the comment defending the private one argued against a per-root map that the shared mechanism one directory over already provided. `mutateRegistry` takes the registry file's own key now; its ten call sites are unchanged, and none sat inside a lock on that path. Separately, `pommora.json` had been read whole and written whole at two sites, each spelling the merge itself; `updateAppConfig` owns it in the shape `updateSettings` already held for the nexus settings, merging onto the raw record so a key this version does not model survives a write.

**Two arms had no tests at all.** `setIcon` and `setHeadingIconHidden` were unexercised, so the suite could not have caught a missed wrapper on either — the hazard window was closed by a structural read of every caller first, and the arms gained coverage afterwards so the next change to this path has a suite that can fail. Every regression test added across the arc was confirmed red against the unfixed code before being kept: without the registry lock, the first of two concurrent property writes disappears.

**The closeout attack found the rule had no enforcement, and it was closed on Nathan's ruling rather than deferred.** Giving two primitives their own key made re-taking a held key an ordinary mistake: the sidecar family's idiom is a lock around a read and a write, and reaching for a self-locking primitive inside it is the obvious move — `removeProperty` carried exactly that shape until this arc removed it. Unrefused, the cost is a wedge rather than a failure, because the nested take queues behind a slot waiting on the queued work, and a chain that never settles hangs every later write to that file for the life of the process. `serializeOnFile` now holds the keys of the call in flight and rejects a second take of one; the check runs before the chain is touched, so a refusal cannot wedge the file it names. Nesting different keys stays legal. The three shapes the attack used to hang the tree each reject, and the suite passing unchanged is the evidence that no production path was nesting.

**One semantic changed deliberately.** An unreadable `pommora.json` now fails the write instead of being overwritten, which is the strict reader's purpose. The read side stays lenient, so a damaged config still degrades to empty defaults at launch, and the write is temp-file plus rename, so no crash can produce the state.

#### Changes Made

- **`main/io/atomicWrite.ts`:** `rmwJsonStrict` runs its read-merge-write inside `serializeOnFile` on the path it writes; the signature is unchanged and the absent-versus-unreadable split is untouched. Its docstring states the non-reentrancy rule and points a caller needing a wider span, or a schema-validated read, at the sidecar pair instead. `rewritePageSerialized` moved here from `io/fileLock.ts`, unchanged, to sit beside the writers it composes.
- **`main/io/fileLock.ts`:** reduced to the chain, so the dependency runs from the writers to the lock and never back. `serializeOnFile` tracks the keys held by the call in flight in an `AsyncLocalStorage` set and rejects a re-entrant take before touching the chain, which is what keeps a refusal from wedging the file it names.
- **`main/contextsRegistry.ts`, `settings.ts`, `crud/contextWrite.ts`, `crud/removeProperty.ts`:** six outer wrappers removed; each function's body is what it always was, minus the layer that had been supplying the key.
- **`main/mutate.ts`:** `patchConfig` deleted. The banner, heading-icon and icon arms call the primitive directly, and the banner's set and clear arms collapsed into one write behind a nullable asset path — `setOrDrop` treats an absent value the same either way, and the replaced-asset delete reduces to the clear arm's own condition.
- **`main/io/propertiesRegistry.ts`:** `mutateRegistry` takes `serializeOnFile(registryPath(root))` in place of a module-level chain; the carry-through that preserves unparsed entries by id is untouched.
- **`main/appConfig.ts`, `index.ts`, `menu.ts`:** `updateAppConfig` replaces `writeAppConfig` as the single writer, taking a mutator and merging onto the raw record; both call sites dropped their local read-and-spread.
- **`main/mutate.test.ts`, `appConfig.test.ts`, `io/propertiesRegistry.test.ts`:** seven tests — the two uncovered config arms, the app config's concurrent writers and its foreign-key carry-through, and a pair crossing both registries to assert neither drops a concurrent sibling's change.

#### Issues Resolved

- **A JSON read-modify-write could run unlocked, and two did:** the primitive named serialization as the caller's job, seven callers supplied it and `crud/reorder.ts`'s two writers of `.nexus/state.json` did not. The lock moved into the primitive, so the omission stopped being expressible.
- **Two mechanisms answered one question about the property registry:** a private module-level chain guarded `.nexus/properties.json` while the shared per-path lock guarded its sibling, leaving two answers to how a registry file is safely rewritten.
- **The app config was read whole and written whole at two sites:** each spelled the merge itself, and the projection they wrote back silently dropped any key the version did not model.
- **`setIcon` and `setHeadingIconHidden` had no tests:** two of the four config arms could not have failed visibly, so the suite could not serve as evidence for the change that touched them.
- **The non-reentrancy rule was a docstring with nothing behind it:** a second take of a held key queued behind a slot that could never settle, hanging every later write to that file silently and permanently. It is refused now, and the refusal leaves the chain intact.
- **`io/fileLock.ts` depended on the writers it exists to protect:** the lock imported the atomic writer for a page helper that belonged beside the other write primitives.
