### PM-003 — MarkdownPM Table parsing fixes, Menu surface consolidation, inaccurate comment fixes

**Dates:** 08-07-2026 → 08-08-2026

#### Summary

Three strands, related by a single theme: a rule stated in more than one place had drifted, and in two of the three the comments were the last thing still asserting agreement.

**Fence parsing and its consumers:** A fenced block ended at the next fence carrying the same marker character, so a five-backtick fence wrapping three-backtick ones was carved into pieces and the sample's own code stranded between them as prose. A fence's marker-run length is now part of its identity: a closer needs a run at least as long as its opener and no info word of its own, which is what lets a longer fence hold shorter ones as literal content. The grammar and the pairing pass moved into `shared/markdownCode.ts`, beside the mask the write side reads.

Four layers had been recognizing fences for themselves — the detector, the folding scan, the subfield statistics, and the write-side mask — and two of them carried comments stating that they agreed with each other. The mask's disagreement was the one able to edit a file: it reported a nested block's lines as not code, which left a `[[Title]]` inside a code sample reachable by a rename cascade. The consumers now read the one pass, including the table-region scan, which decides whether a candidate header sits inside code before treating it as a table. The work was built against mdast, the parser already in the tree that had the rule right, and swept line by line over forty constructed documents covering quoted and callout fences, tildes, indentation, list items, tables, math, embeds, and unclosed openers. That sweep caught two defects in the fix itself: an end-anchored info capture that blanked every fence in a CRLF document, and a backtick inside an info string reading as a fence where the parser sees prose. Both are pinned.

**The dropdown shell:** `ViewDropdown`, `SpaceDropdown`, and `OutlineDropdown` each held the same open state, wrapper ref, outside-dismiss, retract beat, and mounted-pane branch around a shared `MenuSurface`. Their CSS was already shared — one stylesheet served all three while carrying the name of one — so the duplication sat in behavior rather than in styling. `MenuDropdown` now owns that shell and the three render their content into it through a callback that hands back a close. The window-edge measurement the Outline needed, which bounds a pane's growth so its right edge keeps a stated gap from the window, moved into the shell behind an opt-in inset.

`MenuSurface` was left state-free. The toolbar trio shares one dismiss region across two panes and owns that state itself, so folding state into the surface would have broken the consumer that most resembles one wanting it. The shell carries no styling at all — every class arrives from the caller — which keeps the toolbar's swallow shift and its drag-region opt-out in the toolbar. `SpaceDropdown` also had the reappear-on-return defect the Outline had, its hooks running above the selection gate; the gate moved above the shell.

**Comments asserting a reach they lacked:** A sweep of the menu layer for universality claims returned two that were false, against a larger number that hold. `MENU_GUTTER` described itself as the single source every dropdown surface routes through while having one consumer, the surface declared beneath it. `MENU_MAX_HEIGHT` called itself the one dropdown height ceiling and named `PaneSlider` as capping its slot at the same value, where `PaneSlider` references neither the constant nor its number.

Both were corrected rather than made true, because the underlying separation is deliberate: a menu only ever drops, while a picker, a text popup, and an icon grid open in whichever direction they fit, and each states the gutter and height its own purpose asks for. The framing was the defect — it read as accidental drift and invited a consolidation that would have flattened a real distinction. No values moved.

#### Changes Made

- **`shared/markdownCode.ts`:** Gained the fence grammar and its pairing. `Fence` carries the marker character, the run length, the quote depth, and the info string; `fenceCloses` requires a matching marker at the same depth, a run at least as long, and an empty info string. `fenceSpans` is the one pairing pass, with `fencedLineMask` as the per-line projection over it, `lineOffsetsOf` and `quoteDepthOf` beside them, and `codeMask` built on the same spans so the render side and the write side cannot disagree about which bytes a rename may touch.
- **`MarkdownPM/detect/index.ts`:** Dropped its own fence recognition and reads the shared pass, keeping `fencedCodeRanges` and the block-math and embed derivations as projections over it.
- **`MarkdownPM/editor/folding.ts` and `Detail/Subfield/subfieldStats.ts`:** Both stopped recognizing fences for themselves and read the shared mask, which is what removed the two comments that had claimed agreement without a shared source to guarantee it.
- **`design-system/components/menu/MenuDropdown.tsx`:** The dropdown shell — open state, outside-dismiss, retract presence, the trigger button, and the anchored `MenuSurface`. Children arrive as a callback receiving a close. An optional `edgeInset` measures how wide the pane may grow before its right edge leaves the window and publishes it to the anchor as `--menu-dropdown-max`. It declares no styles; each class is a caller's.
- **`Toolbar/ViewDropdown.tsx`, `SpaceDropdown.tsx`, `OutlineDropdown.tsx`:** Each reduced to its own content and the classes it passes. `ViewDropdown` keeps its right-click configuration menu through the shell's button slot; `OutlineDropdown` passes the edge inset; `SpaceDropdown`'s selection gate moved above the shell.
- **`Toolbar/viewDropdown.css.ts`:** Renamed `toolbarDropdown.css.ts`, having served all three dropdowns under the name of one. Its `wrapper`, `anchor`, `button`, and `buttonSlot` are unchanged.
- **`design-system/components/menu/menuSurface.css.ts` and `menu.css.ts`:** `MENU_GUTTER` and `MENU_MAX_HEIGHT` describe what they govern and why neighbouring surfaces state their own. No values changed.

#### Issues Resolved

- **A longer fence could not hold shorter ones:** A block ended at the next fence sharing its marker character, so a `` ````` `` fence wrapping ``` ``` ``` blocks was split into pieces with the inner sample's content read as prose. Run length became part of a fence's identity, and a closer now needs a run at least as long as its opener and no info word.
- **The write-side mask disagreed with the renderer about nested code:** The mask reported a nested block's lines as not code, so a `[[Title]]` displayed inside a code sample was reachable by a rename cascade and could be rewritten in the file. Both sides now read one pairing pass.
- **An end-anchored info capture blanked every fence in a CRLF document:** The fence pattern terminated its info capture at a line end, which cannot match past a carriage return, so no line in a CRLF body registered as a fence at all. Found by the forty-document sweep before the change shipped.
- **A backtick inside an info string read as a fence:** A line whose info string carried a backtick was treated as a fence where the parser reads prose, since the run would be ambiguous with an inline span. Backtick fences now refuse an info string containing one; tilde fences carry no such restriction.
- **Three dropdowns each held their own shell:** The same open state, dismissal, retract beat, and mounted-pane branch appeared in all three, so a correction to one reached neither of the others — which is how the Outline's reappear-on-return defect survived in `SpaceDropdown` after being fixed. One shell now owns it.
- **`MENU_GUTTER` claimed a routing that did not exist:** It described itself as the single source all dropdown surfaces route through while having one consumer, which invited a consolidation of gutters that differ on purpose.
- **`MENU_MAX_HEIGHT` named a consumer it never had:** It called itself the one dropdown height ceiling and cited `PaneSlider` as sharing it, where `PaneSlider` references neither the constant nor its value, and its own neighbouring docstring said panes set their own.
