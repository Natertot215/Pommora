### PM-003 — Menu Surfaces: Shell Consolidation & Comment Fixes

**Dates:** 08-08-2026

#### Summary

`ViewDropdown`, `SpaceDropdown`, and `OutlineDropdown` each held the same open state, wrapper ref, outside-dismiss, retract beat, and mounted-pane branch around a shared `MenuSurface`. Their CSS was already shared — one stylesheet served all three while carrying the name of one — so the duplication sat in behavior rather than in styling, which is what had kept it out of sight. `MenuDropdown` now owns that shell and the three render their content into it through a callback that hands back a close. The window-edge measurement the Outline needed, which bounds a pane's growth so its right edge keeps a stated gap from the window, moved into the shell behind an opt-in inset.

`MenuSurface` was left state-free. The toolbar trio shares one dismiss region across two panes and owns that state itself, so folding state into the surface would have broken the consumer that most resembles one wanting it. The shell carries no styling at all — every class arrives from the caller — which keeps the toolbar's swallow shift and its drag-region opt-out in the toolbar rather than importing toolbar geometry into the design system. `SpaceDropdown` also carried the reappear-on-return defect the Outline had, its hooks running above the selection gate; the gate moved above the shell.

**What a container offers:** The sidebar's native context menu gave a Set one creator, New Page, while the subfield's add button gave the same Set both a page and a nested container. A Set nests to any depth, so the sidebar was the one in the wrong — and the split had survived because the two menus each stated the rule for themselves. `containerCreators` is now that rule, held in `shared/mutate.ts` beside the requests it returns and read by both processes, the way `createSpaceLabel` was already shared for Spaces. Whichever surface asks, a Collection and a Set offer the same pair; only the nested container's name differs, since a Set inside a Set is a Sub-Set.

Two label defects surfaced in the same sweep and belong to the same class. The context menu wrote `New Set` as a literal where the subfield resolved the per-nexus label, so a nexus that renamed Set would have had its two menus disagree about what the thing is called; the sidebar's New Collection was literal in the same way. Both read the registry now, and the subfield's tooltip derives from the menu it describes rather than restating it. `readNexusLabels` gives main the labels without a tree walk, which `ensureContextsRegistry` had been doing by hand and now shares.

**The comments:** A sweep of the menu layer for universality claims returned two that were false, against a larger number that hold. `MENU_GUTTER` described itself as the single source every dropdown surface routes through while having one consumer, the surface declared beneath it. `MENU_MAX_HEIGHT` called itself the one dropdown height ceiling and named `PaneSlider` as capping its slot at the same value, where `PaneSlider` references neither the constant nor its number, and its own neighbouring docstring already said panes set their own.

Both were corrected rather than made true. The separation underneath them is deliberate: a menu only ever drops, while a picker, a text popup, and an icon grid open in whichever direction they fit, and each states the gutter, the height, and the beak clearance its own purpose asks for. The framing was the defect — it read as accidental drift and invited a consolidation that would have flattened a real distinction into a shared helper every consumer then argued with. No values moved.

#### Changes Made

- **`design-system/components/menu/MenuDropdown.tsx`:** The dropdown shell — open state, outside-dismiss, retract presence, the trigger button, and the anchored `MenuSurface`. Children arrive as a callback receiving a close. An optional `edgeInset` measures how wide the pane may grow before its right edge leaves the window and publishes it to the anchor as `--menu-dropdown-max`. It declares no styles; each class is a caller's.
- **`Toolbar/ViewDropdown.tsx`, `SpaceDropdown.tsx`, `OutlineDropdown.tsx`:** Each reduced to its own content and the classes it passes. `ViewDropdown` keeps its right-click configuration menu through the shell's button slot; `OutlineDropdown` passes the edge inset and its rail-bearing pane class; `SpaceDropdown`'s selection gate moved above the shell.
- **`Toolbar/viewDropdown.css.ts`:** Renamed `toolbarDropdown.css.ts`, having served all three dropdowns under the name of one. Its `wrapper`, `anchor`, `button`, and `buttonSlot` are unchanged, as is the swallow transform keyed to the wrapper class.
- **`shared/mutate.ts`:** `containerCreators(kind, parentPath, labels)` returns the New-Page and nested-container offers for a Collection or a Set, naming the nested one from `pageSet.singular` or the derived Sub-Set label. `Creator` names the shape both processes pass around.
- **`main/readNexus.ts` and `main/contextsRegistry.ts`:** `readNexusLabels` reads the nexus labels straight from settings for callers outside the tree walk; `ensureContextsRegistry` had been performing that read inline and now shares it.
- **`main/contextMenu.ts`:** `creatorsFor` routes Collections and Sets through the shared rule; the Context case still resolves its Space label from the registry.
- **`Detail/Subfield/subfieldItems.tsx`:** The add button reads the same rule, and its tooltip is built from the creators it will show rather than restating their names.
- **`Sidebar/Sidebar.tsx`:** The root New Collection creator takes its label from `pageCollection.singular`.
- **`design-system/components/menu/menuSurface.css.ts`:** `MENU_GUTTER` names the surface it governs and states why the picker, the text popup, and the icon grid each sit tighter.
- **`design-system/components/menu/menu.css.ts`:** `MENU_MAX_HEIGHT` reads as `MenuScrollFrame`'s default, with the panes that pass their own declining a default rather than breaking a rule. The dead `PaneSlider` clause is gone.

#### Issues Resolved

- **Three dropdowns each held their own shell:** The same open state, dismissal, retract beat, and mounted-pane branch appeared in all three, so a correction to one reached neither of the others — which is how the Outline's reappear-on-return defect survived in `SpaceDropdown` after being fixed there. One shell now owns it.
- **A stylesheet named for one of its three consumers:** `viewDropdown.css.ts` held the wrapper, anchor, and button geometry for every toolbar dropdown, so the styling looked consolidated while the behavior beside it was written three times. The name now matches the reach.
- **A Set could not be created inside a Set from the sidebar:** The context menu offered a Set only New Page, though Sets nest to any depth and the subfield's add button offered the nested container all along. Both surfaces now read one rule.
- **Two creator labels were written literally:** The context menu's `New Set` and the sidebar's `New Collection` ignored the per-nexus labels that every other creator resolves, so renaming either entity would have left surfaces disagreeing about its name.
- **`MENU_GUTTER` claimed a routing that did not exist:** It described itself as the single source all dropdown surfaces route through while having one consumer, which invited a consolidation of gutters that differ on purpose.
- **`MENU_MAX_HEIGHT` named a consumer it never had:** It called itself the one dropdown height ceiling and cited `PaneSlider` as sharing it, where `PaneSlider` references neither the constant nor its value.
