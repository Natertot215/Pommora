### PM-002 — The Code Mask on the Hot Path

**Dates:** 08-08-2026

#### Summary

`isInsideCode(offset, text)` was defined as `codeMask(text)(offset)`. It built the whole body's code map — fence pairing across every line, then an inline-span scan of each unfenced line, then an array of ranges — to answer a single yes-or-no question about one position, and discarded the result. Four of the editor's input handlers call it on every typed character, and the table-region scan called it once per line of the document.

The module's own contract had already named the problem: `codeMask` is documented as the form to build once per body and query per match, and `isInsideCode` as the form for a caller holding one position. The single-offset form was not honoring its own description, and two callers holding runs of offsets were reaching for the wrong one.

Fence pairing genuinely has to begin at the document's first line, since no line can tell whether it sits inside a block without them. Inline spans are a line-local question. `isInsideCode` now pairs fences as before and scans only the offset's own line for inline spans, which removes the per-line character walk across the rest of the document. The two forms answer identically by construction, and a pin asserts it offset for offset over a body carrying nested runs, a tilde block, a quoted fence, and a span left unclosed at the end, on LF and CRLF alike.

The two callers holding runs were switched to the documented form. `tokenize` builds one mask per body and threads it to the regex and wiki-link passes, which also collapsed six repetitions of its text argument into a local helper; `tableRegions` hoists one mask above its line loop.

**Measured:** The change was measured in the running application against a throwaway page in the test nexus rather than inferred from the shape of the code. On a 67KB, 941-line body — the size of a working session document — forty real keystrokes cost 0.158ms each before and 0.043ms after, and a tokenize call over the visible span cost 0.285ms before and 0.120ms after. On a 2.7KB page the same measurement returned 0.012ms against 0.010ms, inside the noise. The saving is proportional to document length rather than fixed, and at neither size was this a visible source of lag; what it removes is a document-length-proportional cost sitting on the most frequent trigger in the editor.

#### Changes Made

- **`shared/markdownCode.ts`:** `isInsideCode` stopped delegating to `codeMask`. It splits the body, pairs fences through the shared `fencedLineMask`, walks to the line holding the offset, and returns true for a fenced line or tests the offset against that one line's `inlineSpans`. A negative offset and an offset past the body both return false, as before. `codeMask` is unchanged and remains the form for a run of offsets.
- **`MarkdownPM/tokens/index.ts`:** `tokenize` builds one `codeMask` per call and passes it to `regexTokens` and `wikiLinkTokens`, which took it as a parameter in place of their per-match `isInsideCode` call. A local `scan` helper binds the body and the mask, which removed the repeated text argument from the six regex passes.
- **`MarkdownPM/Tables/regions.ts`:** `tableRegions` resolves one mask before its line loop and queries it per candidate header, where it had built a fresh one for every line of the document.

#### Issues Resolved

- **The single-offset code test walked the whole document:** Answering whether one position sits in code cost a full body scan, including an inline-span walk of every line, on every typed character across four input handlers. Only the fence half needs the document; the inline half is line-local and is now scanned that way.
- **The tokenizer rebuilt the mask for every match:** `regexTokens` and `wikiLinkTokens` called the single-offset form inside their match loops, which is the O(document × matches) case the mask's own documentation warns against. Both now receive one mask built per body.
- **The table scan rebuilt the mask for every line:** `tableRegions` tested each candidate header with the single-offset form inside its walk, so a document with many lines paid the whole-body scan once per line. One mask is now resolved before the loop.
