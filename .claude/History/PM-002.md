### PM-002 — MarkdownPM: The Shared Code Pass

**Dates:** 08-07-2026 → 08-08-2026

#### Summary

Two questions about the same subject, answered in the same file across two days: *where does code begin and end*, and *what does asking cost*. The first had four layers each deciding for themselves; the second had one function doing the most expensive possible thing on the most frequent trigger in the editor.

**Fence identity:** A fenced block ended at the next fence carrying the same marker character, so a five-backtick fence wrapping three-backtick ones was carved into pieces and the sample's own code stranded between them as prose. A fence's marker-run length became part of its identity: a closer needs a run at least as long as its opener and no info word of its own, which is what lets a longer fence hold shorter ones as literal content. The grammar and the pairing pass moved into `shared/markdownCode.ts`, beside the mask the write side reads.

Four layers had been recognizing fences for themselves — the detector, the folding scan, the subfield statistics, and the write-side mask — and two of them carried comments stating that they agreed with each other. The mask's disagreement was the one able to edit a file: it reported a nested block's lines as not code, which left a `[[Title]]` inside a code sample reachable by a rename cascade. Every consumer now reads the one pass, the table-region scan among them, since it decides whether a candidate header sits inside code before treating it as a table.

The work was built against mdast, the parser already in the tree that had the rule right, and swept line by line over forty constructed documents covering quoted and callout fences, tildes, indentation, list items, tables, math, embeds, and unclosed openers. That sweep caught two defects in the fix itself: an end-anchored info capture that blanked every fence in a CRLF document, and a backtick inside an info string reading as a fence where the parser sees prose. Both are pinned.

**The cost of asking:** `isInsideCode(offset, text)` was defined as `codeMask(text)(offset)`. It built the whole body's code map — fence pairing across every line, then an inline-span scan of each unfenced line, then an array of ranges — to answer a single yes-or-no question about one position, and discarded the result. Four of the editor's input handlers call it on every typed character, and the table-region scan called it once per line.

The module's own contract had already named the problem: `codeMask` is documented as the form to build once per body and query per match, and `isInsideCode` as the form for a caller holding one position. The single-offset form was not honoring its own description, and two callers holding runs of offsets were reaching for the wrong one.

Fence pairing genuinely has to begin at the document's first line, since no line can tell whether it sits inside a block without them. Inline spans are a line-local question. `isInsideCode` now pairs fences as before and scans only the offset's own line for inline spans, which removes the per-line character walk across the rest of the document. The two forms answer identically by construction, and a pin asserts it offset for offset over a body carrying nested runs, a tilde block, a quoted fence, and a span left unclosed at the end, on LF and CRLF alike. The two callers holding runs were switched to the documented form: `tokenize` builds one mask per body and threads it to the regex and wiki-link passes, and `tableRegions` hoists one mask above its line loop.

**Measured:** The second change was measured in the running application against a throwaway page in the test nexus rather than inferred from the shape of the code. On a 67KB, 941-line body — the size of a working session document — forty real keystrokes cost 0.158ms each before and 0.043ms after, and a tokenize call over the visible span cost 0.285ms before and 0.120ms after. On a 2.7KB page the same measurement returned 0.012ms against 0.010ms, inside the noise. The saving is proportional to document length rather than fixed, and at neither size was this a visible source of lag; what it removes is a document-length-proportional cost sitting on the most frequent trigger in the editor.

#### Changes Made

- **`shared/markdownCode.ts`:** Gained the fence grammar and its pairing. `Fence` carries the marker character, the run length, the quote depth, and the info string; `fenceCloses` requires a matching marker at the same depth, a run at least as long, and an empty info string. `fenceSpans` is the one pairing pass, with `fencedLineMask` as the per-line projection over it, `lineOffsetsOf` and `quoteDepthOf` beside them, and `codeMask` built on the same spans so the render side and the write side cannot disagree about which bytes a rename may touch. `isInsideCode` later stopped delegating to `codeMask`: it splits the body, pairs fences through `fencedLineMask`, walks to the line holding the offset, and returns true for a fenced line or tests the offset against that one line's inline spans. A negative offset and an offset past the body both return false.
- **`MarkdownPM/detect/index.ts`:** Dropped its own fence recognition and reads the shared pass, keeping `fencedCodeRanges` and the block-math and embed derivations as projections over it.
- **`MarkdownPM/editor/folding.ts` and `Detail/Subfield/subfieldStats.ts`:** Both stopped recognizing fences for themselves and read the shared mask, which removed the two comments that had claimed agreement without a shared source to guarantee it.
- **`MarkdownPM/tokens/index.ts`:** `tokenize` builds one `codeMask` per call and passes it to `regexTokens` and `wikiLinkTokens`, which took it as a parameter in place of their per-match `isInsideCode` call. A local `scan` helper binds the body and the mask, removing the repeated text argument from the six regex passes.
- **`MarkdownPM/Tables/regions.ts`:** `tableRegions` resolves one mask before its line loop and queries it per candidate header, where it had built a fresh one for every line of the document.

#### Issues Resolved

- **A longer fence could not hold shorter ones:** A block ended at the next fence sharing its marker character, so a `` ````` `` fence wrapping ``` ``` ``` blocks was split into pieces with the inner sample's content read as prose. Run length became part of a fence's identity, and a closer now needs a run at least as long as its opener and no info word.
- **The write-side mask disagreed with the renderer about nested code:** The mask reported a nested block's lines as not code, so a `[[Title]]` displayed inside a code sample was reachable by a rename cascade and could be rewritten in the file. Both sides now read one pairing pass.
- **An end-anchored info capture blanked every fence in a CRLF document:** The fence pattern terminated its info capture at a line end, which cannot match past a carriage return, so no line in a CRLF body registered as a fence at all. Found by the forty-document sweep before the change shipped.
- **A backtick inside an info string read as a fence:** A line whose info string carried a backtick was treated as a fence where the parser reads prose, since the run would be ambiguous with an inline span. Backtick fences now refuse an info string containing one; tilde fences carry no such restriction.
- **The single-offset code test walked the whole document:** Answering whether one position sits in code cost a full body scan, including an inline-span walk of every line, on every typed character across four input handlers. Only the fence half needs the document; the inline half is line-local and is now scanned that way.
- **The tokenizer rebuilt the mask for every match:** `regexTokens` and `wikiLinkTokens` called the single-offset form inside their match loops, which is the O(document × matches) case the mask's own documentation warns against. Both now receive one mask built per body.
- **The table scan rebuilt the mask for every line:** `tableRegions` tested each candidate header with the single-offset form inside its walk, so a document with many lines paid the whole-body scan once per line. One mask is now resolved before the loop.
