## Unwrapped Frontmatter — Decision Log

### Frame

- **Purpose:** Rethink the property-keying architecture — unwrap `<Property>` keys to bare Obsidian-style keys, move Context keys to `<Context>`, and make external edits to property frontmatter first-class: read leniently by one rule, repaired on the file's next governed write, visible live.
- **Core Value:** A universally translatable frontmatter format with less machinery — the registry match becomes the one ownership gate where today shape and registry are two, one writer where today there are two, one reconcile where a sibling would otherwise be built.
- **Success Criteria:** Bare property keys on disk, list-shaped option values, `<Context>` keys. External writes to registered properties appear live when valid; invalid shapes resolve by one stated rule. **Complexity reduction** — one sigil, one ownership gate, one governed-page writer, one reconcile, one shape rule for the option types, one values-refresh seam — with a **net reduction** in code and tests required but no set amount (lines may land near break-even; concepts may not). **Acceptance gate (Nathan, 08-31-2026):** an independent agent dropped into the before and the after with no stake in either, asked "which version is more sustainable," answers *after* unprompted.

### Decisions

Every entry is a settled call unless tagged `[assumed]`. Evidence stays inline; provenance of dropped alternatives lives in Considered & Rejected.

#### K — Keying & Identity

- **K-1 Bare property keys.** A bare key is Pommora's iff it exactly matches a registered property name (NFC-normalized). A `<X>` key is Pommora's iff `X` exactly matches a registry Context title. Foreign is a definition, not a mechanism: any key neither registry names.
- **K-2 Contexts move `(X)` → `<X>`.** One sigil, one layer; `parseGovernedKey` / `isGovernedKey` lose their layer dispatch and fold into `contexts.ts` as `contextKey` / `isGovernedContextKey` / `parseContextKey`. `normalizePropertyName`, `invalidPropertyName`, `KEY_REFUSAL` move to `properties.ts`. `governedKeys.ts` is deleted. The two namespaces stay disjoint by the sigil, so no cross-registry uniqueness is needed. Contexts change nothing else this cycle.
- **K-3 Exact-case matching.** No key case-folding, no dual translation, no `tags`/`Tags` merge machinery — want Obsidian's `tags`, name the property `tags`. A case-drifted key is foreign, as `contextResolve.ts:14` already rules for Contexts.
- **K-4 Names take any casing.** No casing enforcement exists today (the registry gate is case-folded uniqueness only, `Properties/schema.ts:17`). A reserved rule joins the existing leading-`$` refusal in `invalidPropertyName` — both mutation surfaces already gate through it (`registryProperty.ts:53,138`): the seven names `KIND_ID_KEY` ∪ `PAGE_MODELED_KEYS` yield (`PageID`, `TaskID`, `EventID`, `icon`, `cover`, `created_at`, `modified_at`), plus any leading `<`. One `KEY_REFUSAL.reserved` string; `@shared`, so the renderer pre-validates.
- **K-5 Obsidian's three special keys are lowercase-or-nothing.** Obsidian rewrites `Tags` → `tags` (and `aliases`, `cssclasses`) in source on any touch, and preserves casing for every other key. A Pommora property wanting one of those three is created lowercase and shown capitalized by U-1. Doc guidance in [[PropertiesPM]], zero code. Also documented: Obsidian's tag reader drops values containing spaces.
- **K-6 A rename claims the key corpus-wide.** Renaming a property rewrites every same-named key on every Collection page, assigned or not (`keyHolderFiles` intersects with all Collection folders, `keyHolders.ts:11`). Naming a property `tags` claims that key across the vault. Accepted.
- **K-7 A rename onto a held key is refused.** `prefer-new` deletes Pommora's value when a *foreign* key already holds the new name; `merge` deletes the foreign one (both executed). Neither policy is safe once the rival can be someone else's data, so the Names rule — rename onto a taken name is refused — generalizes from files to keys. Mechanics: `keyHolderFiles` returns *candidates* (with no ready index it returns the whole Collection corpus), so the refusal confirms holders **per file**, unconditionally — a rename is a rare user gesture and `cascadePages` already reads every candidate on an option rename. It runs **before `stageRename`** writes the journal (`registryProperty.ts:88–121`), because `mutateRegistry`'s callback is synchronous and a refusal after staging strands a journal the next open replays. `prefer-new` stays for the one case its comment describes: a value written *during* the sweep under the already-committed new name.

#### V — Values & Shapes

- **V-1 Select and Status are list-shaped on disk.** `encodeValue` writes a single-element block list; `decodeValue` accepts a list or a scalar for all three option types and applies cardinality by definition. An Obsidian List-typed `Status` and a Pommora Select `Status` are then one shape — no type-mismatch flag, no scalar↔list ping-pong; every bare Obsidian `Status:` in the vault is already a list. On disk Select and Multi-Select are indistinguishable; only the registry knows, which is the existing rule ("the definition decides, nothing is inferred from a value's shape"). Three consumers read the raw shape and all three take the same normalize-to-list step: `decodeValue`, `encodeValue`'s select case (`propertyValue.ts:115–125`, currently a bare string), and `pageValue.rewriteRaw` (`:19–40`, whose scalar compare would otherwise make option rename and delete silently skip every list-shaped page — executed). With the array path universal, `rewriteRaw`'s `type` parameter is dead and retires from `stripPageValue` / `replacePageValue`, `CascadeTarget`, and `replaySchemaCascade`. No production consumer of `encodeValue` expects a string (five sites audited). ~62 scalar test fixtures across 13 files become lists.
- **V-2 One shape rule for the three option types.** Normalize to a list, then cardinality: Select/Status keep the **last valid** element — the newest, since an appending writer's entry sits last; an invalid trailing element yields to the nearest valid one before it (`[Active, Wip]` against Open/Active/Done → Active; `[Green, Blue]` against Red/Blue → Blue). Multi-Select keeps every valid element. No record of a pre-edit value exists anywhere (the content index tracks current disk; the deletion record baselines opens), so position is the only honest signal. This subsumes the Multi-Select bare-string Known Issue.
- **V-3 Unknown options by type.** Select/Status: an unknown value reads as no value, displays nothing, and the key is deleted on the file's next governed write (no value, no key) — accepted eyes-open that it is invisible until scrubbed and an edit over the blank cell replaces it. Multi-Select: an unknown value is **adopted** into the property's options in `properties.json` on the repair trigger; until then it renders through today's fallback (`Cell.tsx:92`, a chip with no registered color). Number / Date / Link / File / Checkbox carry no membership concept — shape only.
- **V-4 Checkbox `false` ≡ absent.** Pommora writes only `true`; `false` arrives from outside. The cell and grouping already treat it as absent (`group.ts:229`), the filter's "is empty" does not (`filter.ts:333`). `decodeValue` reads `false` as no value; repair deletes the key. Number `0` stays a real value.
- **V-5 Unassigned stays untouched.** Registry governs identity nexus-wide; assignment governs display. A registered property's value in a Collection that doesn't assign it is real, unvisualized, and never rewritten — the reconcile's property arm takes the page's Collection assignment list and skips unassigned keys. Pages outside any Collection (the Agenda folders) get an empty defs map [assumed].
- **V-6 Serialization style is unchanged.** Pommora and Obsidian's editor produce byte-identical YAML for every shape either writes (executed diff, Sources). Obsidian drops YAML comments on every rewrite; Pommora's in-place editing preserves them — a real guarantee that holds only until Obsidian's next touch. Datetimes are already zoneless (`CalendarPicker.tsx:181`); the `…Z` in [[PropertiesPM]] is a stale doc line. The governed stamps `created_at`/`modified_at` stay UTC-`Z` machine bookkeeping. Obsidian's bare `key:` and `[]` for emptied properties meet Pommora's no-empties rule on the next governed write, as today.

#### R — Repair

- **R-1 Lenient read, repair on the file's next governed write.** A mangled value displays by V-2's rule; the file canonicalizes only when a property or Context value is deliberately set on it. Body edits, renames, moves, creates, sweeps, and cascades never repair (`updatePageBody`, `relocatePage`, `createPage` govern only `modified_at` / birth keys). A file the user only ever types in never self-repairs until a value edit or the R-6 sweep — accepted. The interim is harmless: nothing reads a drifted value as anything but V-2's resolution.
- **R-2 Scope is the whole file, both layers.** A governed page write reconciles every governed key on that file — every registered, assigned property key and every context key — touching only the keys that are drifted. "I changed Priority" may also reshape `Status`, adopt an unknown tag, or scrub an unknown Space; those pages were being rewritten anyway, and a repair is deterministic and lossless by rule. Contexts already behave this way (`governedContextKeys` widens to every context key on a context write), so both layers share one behavior.
- **R-3 The strict Contexts world loads only when drift is present.** The one expensive step is `loadContextWorld` (a per-Context `readdir` plus a strict JSON read per Space; strict by design — a missed Space would strip valid tags, `contextWrite.ts:64–72`, guarded by `contextWrite.test.ts:147`). Before loading it, a property write runs a **drift pre-check** against the titles already in `getLiveTree()`: for each `<X>` key whose `X` is a Context title, every value must be byte-equal to a Space title. All exact → the context arm is skipped. Rules the argument needs: (a) a present-but-empty list fails the pre-check (Obsidian writes `[]`; no-empties must delete it); (b) a null live tree (pre-walk; `getLiveTree` has no disk fallback) means load the strict world, never "clean"; (c) a `<X>` key naming no Context title is skipped — the reconcile passes it through verbatim, so comparing it would make one foreign key cost the strict load forever; (d) if the strict load **fails** on a property write (a corrupt `_space.json` the lenient walk dropped), the context arm is skipped and the property write proceeds — the repair is deferred, never the edit; a context write still refuses, as today. Safety: the lenient tree can only produce false positives (a Space it lacks fails the exact check → strict load → the strict world knows it → nothing drops); a drifted value can never be byte-equal to a title. Live-tree and strict-world titles can't diverge by NFC/trim — both take the raw `readdir` name. A context write loads the strict world as today.
- **R-4 One reconcile.** `reconcileContextKeys` (`contextResolve.ts:58–88`) generalizes: its key-wise loop gains a property arm — registered and assigned name → `decodeValue` (non-strict), blank → drop, else re-encode and compare — beside the existing context arm and verbatim pass-through. It takes one `GovernedWorld` (`contextWrite.ContextWorld` + `defs: Map<name, def>` scoped to the page's Collection, the shape `restoreScrub.liveWorld` already builds; `loadContextWorld` becomes the one loader) and returns `{ root, changed, adoptions }`. The property arm is inert on Space sidecars (an empty defs map). `encode(decode(strict))` is **not** the repair: `strict` drops unknown Multi-Select options, the opposite of adoption. `decodeValue`'s three wrong-shape `return NULL` arms become the coercion arms (`fileEntry` at `:42` is the in-file precedent).
- **R-5 One writer, and repair is its parameter.** Phase 0: `setPageContext` delegates its merge+write (`contextWrite.ts:156–165`) to `setGovernedRootKeys` — same lock key, same unconditional `modified_at` stamp, byte-identical `mergeFrontmatter` construction, `setGovernedRootKeys` takes no lock so the nested call is legal; ≈ −6 lines, zero test changes, `writePathRace.test.ts:82` is the regression guard. Then `setGovernedRootKeys(absFile, next, govern, world?)` runs the reconcile when a world is passed; the two user value-edit entries (`mutate.setProperty`, `setPageContext`) pass one, `restoreProperty.ts:81` (which calls `updatePageProperty` per page inside a schema slot) passes none. **Precedence, all three required (executed on both arms):** (1) `setPageContext` passes `govern = [targetKey]` only — never the wide `governedContextKeys` set, or every context key is reasserted from `raw` and repair goes vacuous; (2) `next` is authoritative for every key in the caller's `govern`, *including by absence* — an unassign is signalled by omission and must delete; (3) the writer widens `govern` by the reconcile's changed/dropped keys and sources only those from the reconciled root. A naive `{...pick(reconciled, govern), ...next}` reverts an unassign or a clear. On the page arm `applyTarget` stops reconciling (the writer owns it); on the Space-sidecar arm (`setSpaceContext:183`, `rmwJsonStrict`) `applyTarget` keeps its reconcile — there is no writer there to inherit it.
- **R-6 An on-load repair sweep, behind a default-off toggle.** Detection rides `seedContentIndex`'s loop (`indexSeed.ts:140–160`), which already reads and parses only files whose (mtime, size) moved; it adds a registry-driven decode over that changed set — O(changed files) per seed, never O(corpus), never inside the walk. A file is drifted iff `encode(decode(raw))` is not **deep-equal** to `raw` for some governed key, compared by `JSON.stringify` on parsed values (a reference test flags every File and every one-element Select page forever — executed; quoting is invisible; strings round-trip untouched, so Obsidian's no-seconds `2026-07-15T09:00` never churns). Flags are transient session state; the writer is `sweepGovernedRoots {kind:'files'}` over them, slotted where `replaySchemaCascade` runs. Never hook `readPageRecord`'s parse closure (a cache hit skips it, `readNexus.ts:328`); never detect via `sweepGovernedRoots {kind:'nexus'}` (whole-corpus read). Honest scope: it repairs files changed since the last open, not every drifted file — a file that drifted while the toggle was off and hasn't moved since is manual-pass territory.
- **R-7 Adoption is a registry-only mutation off the schema chain.** A repair fires inside a page lock; the schema chain's cascades take page locks; a page-locked repair awaiting the chain while a chain-held rename awaits that page deadlocks silently (executed: the chain wedges process-wide). Adoption is `addOptionToDef(root, propertyId, value)` — `mutateRegistry` alone (page lock → registry-file lock, no edge back), mirroring `dropOptionFromDef` (`optionOps.ts:105–131`), Multi-Select only, idempotent on "already present". Every reconcile seam is synchronous, so the reconcile *returns* `adoptions` and the caller applies them in one awaited `mutateRegistry` afterward, only when non-empty; `sweepGovernedRoots`' `Rewrite<C>` `capture` / `SweepResult.captured` already carries them across a sweep. Registry-first: the option exists before the page value is treated as canonical. `setOptions` is never the carrier (wholesale replace outside the lock, and it rides the chain).
- **R-8 One adjudicator for "does this value stand."** `standing.ts` declares itself the one answer for every path that puts a value back, but `propertyValueStands` uses `decodeValue(strict)`, which drops an unknown Multi-Select option — the restore paths would lose `zeta` where a live edit adopts it. The generalized reconcile **is** the standing check: `propertyValueStands` collapses into it and the restore paths (`restoreScrub`, `restoreProperty`, `removeProperty.restoreCachedValues`) apply its `adoptions` through R-7. `restoreScrub` runs outside the schema chain (`provenance.ts:608`) — a restore-time adoption can interleave with an option cascade; the registry stays consistent under its own lock and only the chain's pages-vs-registry invariant is unheld on that path. Accepted. [assumed]
- **R-9 The content index is registry-independent.** `governedValues` (`indexSeed.ts:47`) records **all** frontmatter keys into `page_values` — the rule `readNexus.ts:363` already states for the parse cache. Load-bearing: registering a property whose bare key already sits in the vault writes no file and moves no mtime, so a registry-filtered index would never re-index those pages and every index-driven cascade would silently miss them forever (`queryKeyHolders` returns `[]`, not `null`, for an indexed-but-unheld key). The gate moves to the two consumers: `keyHolderFiles` (already keyed by a resolved def's name) and `cascade.renameCascade` (one `readRegistry` before its loop, one `.filter` — the page-rename connection rewrite going registry-driven). An **index generation** (a `meta` row beside `schema_version`) forces the rebuild on first launch by truncating `page_values` and `indexed_files` — never by bumping `SCHEMA_VERSION`, whose mismatch path removes the whole database and with it the page aliases and every dashboard layout `local_state` holds (executed 08-31-2026). The index's own invalidation, not migration code.
- **R-10 Four property-shape sites become registry-driven; the context-shape sites need only the sigil constant.** `governedSweep.changedKeys` drops its shape filter outright (its value diff already gates); `restoreScrub.liveWorld` re-keys its defs map by name and `Map.get` is the predicate; `exclusionScan` reads the registry once per Clear; `indexSeed` per R-9. The predicate itself is a pure `(key, names: ReadonlySet<string>) => boolean` in `properties.ts`; both processes already hold the names (`readRegistry(root).defs`; `tree.registry`). `propertyKey(def)` collapses to `def.name` at its twelve call sites.

#### L — Live Values

- **L-1 The watcher gains frontmatter-awareness through one values-changed push.** `PageNode` carries no values, and node identity moves on app-side confirms too, so the tree push can't signal "values changed" without refetching on every cell edit. One new `Pushes` entry in `bridge.ts`, a preload subscriber, a main-fed store action. `valuesEpoch` becomes `{ kind:'rename', oldKey, newKey } | { kind:'container', rel, pageIds }`; `useValuesEpoch` refetches on both and re-keys the override only under `rename`. Open views on the named container refetch `loadValues` — one container-wide reload per bump, fine-grained patching only if this proves slow. `GroupFrame.tsx:779` is a second `loadValues` consumer with no subscription today; it subscribes.
- **L-2 Both legs feed it.** The watcher leg: `settle` pushes once per batch, keyed on its `page-upsert` rels; `patchPageFromDisk` already holds each `record.node.id` (`watchPatch.ts:284`). The write leg: `writeEcho` makes the watcher structurally blind to app writes, so main's own operations push too — **operation-level** (`confirmWrite`, `index.ts:523`, once per op), never per file (a 500-page rename would push 500 times; nothing on the write path coalesces). An op emits one bump per container it touched, with page ids resolved from paths through the live tree (`SweepResult.touched` is paths; `cascadePages` returns a count). This is what lets `useViewHost.refreshValues` and its five-site prop chain through CardsView die — its only consumer is a cover save.
- **L-3 An external bump retires optimistic overrides by page id, and only settled ones.** `valueOverride` (`useViewHost.ts:175`) is whole-frontmatter per page id, cleared only on container change; a value mutate emits no push and no watcher event, so "differs from the refetch" can't tell an external edit from an unlanded write — clearing on that basis is the assign-vanish bug already fixed once (`useViewHost.test.tsx:165`). Rule: the push carries page ids; the renderer retires overrides for those ids. Overrides gain an **in-flight marker**, set when the patch is written and cleared when that page's own mutate promise resolves, because a batch containing one `full-refresh` event degrades to a full walk with no ids and must retire only settled overrides. `TableView.patchBandValue` (`TableView.tsx:1151`) mints an override with no mutate and is covered by the same marker. An external edit landing on a page with an in-flight override: the external one landed later — most-recent-wins retires it.

#### Prospects (allowed later, not now)

- **Text property type** — free-text values (`description:`, `name:`) have no type to land on; the majority Obsidian case stays foreign. Recorded in `ContextPM` §Pending. Don't-foreclose: `decodeValue` stays type-dispatched.
- **Full context unwrap** — bare `Areas:`/`Projects:` reading NexusOS natively. The sigil swap keeps it cheap.
- **Auto-assign-on-discovery** — an external write to an unassigned property assigning it to the Collection. Deferred: external edits would mutate sidecars.
- **Echo-window fix** — the 2000ms / 800ms window drops an external write landing right after an app write; hash-compare or a narrower window.
- **`types.json` cohabitation (Sapphire's cycle)** — writing `.obsidian/types.json` entries from `properties.json` so Obsidian shows Pommora's widgets.
- **Case-variant warning for Obsidian's special keys** — a soft warn on `Tags`/`Aliases`/`Cssclasses` in Title Case; doc-only until it bites.
- **Page aliases in `aliases:` frontmatter** instead of `nexus.db` — would delete a store and match the universal convention.

#### Out of Scope (won't do — distinct from Prospects)

- **Contexts-become-properties** — folding the Context registry into the property registry. Contexts change nothing but the sigil this cycle.
- **A Settings > Properties rules configurator** — one deterministic rule instead; the sweep toggle is the only knob.

#### Considered & Rejected

- **Case-folding dual translation** (`tags` ↔ `Tags` merging, secondary-casing writes) — merge policies, two-key collisions, a canonicalization layer. Exact match plus free casing gets the same outcome.
- **A translation layer over wrapped keys** (recognize bare twins, canonicalize to wrapped on write) — adds code, keeps the sigil, wins nothing.
- **Repair on load as the default** — writes inside the read path, churns untouched files; write-on-load stays reserved for identity (adoption, remint) and the opt-in sweep.
- **"Keep the original value" via a record** — no record holds pre-edit values. Positional rules only.
- **First-wins on a multi-element single-value list** — position one is not "the original" once appending writers exist; the newest valid entry is the one the user meant.
- **Written-key-only repair scope** — setting a value replaces it, so repair would do no work for properties; every drifted sibling would persist until the sweep, and Contexts would tidy the whole file while properties tidied nothing.
- **Per-layer repair scope** (a property write repairs only property keys) — cheaper without a gate, but two behaviors where one was wanted; superseded by the drift pre-check.
- **Serving the strict Contexts world from the lenient live tree** — a lenient miss strips valid tags (`contextWrite.test.ts:147`). The tree is a detector only.
- **Adoption on the schema chain** — deadlocks from inside a page lock; `mutateRegistry` alone is the carrier.
- **`encodeValue(decodeValue(strict))` as the repair** — strict drops the values adoption exists to keep.
- **Skipping K-7's holder check when the index is cold** — reopens the collision exactly in the post-reset window where the index is guaranteed cold.
- **Quoting every scalar** to match "what other apps write" — Obsidian doesn't; both writers already produce identical bytes.
- **Adoption backfilling `created_at`** after a Clear — "Clear is clear."
- **Unwrapping Contexts fully this cycle**, and **auto-adopting unknown Select options** — Nathan's calls; Select and Status are curated vocabularies.

#### Lessons

- **A Features doc's on-disk examples are claims, not evidence** — [[PropertiesPM]] showed `…Z` datetimes the code never wrote; one vault grep would have caught it. Verify format claims against a real file or the writer before designing around them. → Guidelines.
- **Auditing keys isn't auditing the format** — the value vocabulary (every type's serialized shape, every governed key's convention) is a separate pass and is where the real cohabitation gaps (Text type, aliases, icon) surfaced. → the brainstorm's sweep for any on-disk-format change.
- **A rule stated in three places drifts three ways** — first-wins/last-valid lived in B-2, a B-3 sub-bullet, and B-14 with three tags; the exit gate caught it only on a whole-document read. One statement per rule, others defer by reference.
