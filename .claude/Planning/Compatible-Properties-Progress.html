What changes

Property values move from Pommora-only keys like <Status>: to plain keys like Status: — the same frontmatter any other Markdown app reads and writes. Context relations move from (Projects): to <Projects>:. Select and Status values become one-element lists so a list edited elsewhere and a Select edited in Pommora are the same thing. Whether a key is Pommora's is decided by one rule — its exact name is registered in properties.json — instead of by the brackets around it. An edit made outside the app shows up in an open view within a second, resolves by one rule when its shape is off (the newest valid value wins), and is tidied on disk the next time a value is deliberately set on that file. Renaming a property onto a key some page already uses is refused instead of destroying data.

The plan, phase by phase

Phase 0One writer. Strip stale comments from every file the plan touches, then collapse the two frontmatter writers into one and delete two duplicate functions. Nothing changes in behavior; the tests prove it by not changing. Phase 1Keying. The brackets come off property keys, Context keys switch to <…>, the registry name becomes the one ownership test, the content index records every key so a newly registered name finds its pages at once, a reserved-name rule and the rename refusal land. Then the one planned stop: the vault is converted (Obsidian's values win, .slate pseudo-contexts also become real Contexts, Brand/Price/Links join the registry), and you look at a page in both apps. Phase 2Values. Select and Status write as lists; one shape rule for the three option types; checkbox false reads as absent; option rename and delete work on list-shaped pages. Phase 3Repair. One reconcile with a property arm runs inside the one writer on every value edit, whole file, with the rules that keep a clear or an unassign from being reverted. Unknown Multi-Select values are adopted into the registry; unknown Select values are dropped. The expensive Contexts load runs only when a quick check finds drift. Phase 4Live values. A values:changed push fed by the file watcher and by the app's own writes, so an external edit reaches an open table without reopening it; optimistic edits are retired by page id and never before their own write lands. Phase 5Surfaces. Two toggles in Settings › Properties › Metadata: Repair Properties On Open (off by default) and Capitalize All Metadata. Then closeout: the Ideas Collection checked against what Obsidian shows, a manual list of behaviors tried in the running app, an independent "which is more sustainable" judgment, surgical doc rewrites, and the History entry Compatible Properties.

How it's judged

Not by line count. The goal is fewer concepts — one sigil, one ownership gate, one writer, one reconcile, one shape rule, one refresh seam — and an outside agent, shown before and after, answering that the after is the more sustainable codebase.
