## Text Selection — Decision Log

### Frame

- **Purpose:** Give Pommora its own app-wide text-selection paint, the way it already owns the caret — an accent-tinted, rounded, caret-bound highlight drawn by the app rather than the browser, reaching every surface a user can select text on, with a Settings toggle that hands the paint back to the platform.
- **Core Value:** One selection identity with one geometry rule and one token family, mounted at the same chokepoints the caret already uses — so the two read as a matched pair and neither can drift from the other.
- **Success Criteria:** A single-line selection is exactly caret-height; a multi-line selection tiles with zero gap and reads as one continuous ribbon; the editor, native fields, the one non-CM contenteditable, and structural cell/row selection all use the same token; `Use Native Highlighting` restores the platform paint with a pure-CSS gate and no remount.

### Sources

- `renderer/Carets.css` — the precedent this mirrors. Two selector lists: the I-beam cursor list and the `caret-color: transparent` list, both enumerating CM content plus the five text `input` types plus `textarea` plus `[contenteditable="true"]`. `--caret-width` / `--caret-color` / `--caret-gap` / `--caret-dim` are the knob family; `.mdpm-caret` and `.mdpm-caret-overlay` are the two painted forms.
- `renderer/nativeCaret.ts` — the native-field half: one document-level focus listener, a metrics **mirror** div carrying 30 copied computed properties, a `<span>` split at `selectionStart` whose left edge marks the caret, rAF-coalesced, `ResizeObserver` on the focused field. `TEXT_TYPES = ['', 'text', 'search', 'url', 'tel']`; `password` deliberately excluded (masked glyph widths mis-measure); `isEditable` excludes anything inside `.cm-editor`.
- `renderer/MarkdownPM/Editor/caret.ts` — the CM half: a `layer()` of `RectangleMarker`s. Header states the design explicitly — only the native **caret** is hidden, *not* the selection, "so this is NOT drawSelection's all-or-nothing takeover." Carries a widget clamp (`cap = defaultLineHeight * 2.5`, `floor = 4`) and a `tileEdgeMarker` special case for embed-tile document edges.
- `renderer/styles.css:35-43` — **the surface gate.** `body { user-select: none }`, re-enabled only on `input`, `textarea`, `[contenteditable="true"]`. The set of selectable surfaces is therefore closed, and it is the same set Carets.css already enumerates.
- `renderer/MarkdownPM/readOnlySelection.test.tsx:37` — pins that MarkdownPM renders selection natively and that read-only embeds must stay focusable contenteditable for it to work. Any move to `drawSelection` would invalidate this test's premise.
- `@codemirror/view` `LayerConfig.above: boolean` — a layer can be seated **below** the text. This is how a drawn highlight paints behind glyphs without tinting them.
- `renderer/DesignSystem/Tokens/personalization.ts` — the apply-map: `ROOT_VARS` (a key that writes CSS vars), `ROOT_CLASSES` (a boolean that writes a root class), `ROOT_VALUE_CLASSES` (a key that writes a class at one particular value). Header states the law: "a key with a DOM effect belongs to exactly one." A boolean toggle is one `ROOT_CLASSES` row and nothing else.
- `renderer/Settings/SettingsWindow.tsx:189` — the Interface frame. Its first section already carries `hideChevrons`, `revealTabBarOnHover`, `nativeMenus` (a `device` row), `pickerSelection`, and the two scale rows. A new toggle is one entry in the `FRAMES` roster.
- `renderer/DesignSystem/Tokens/tint.ts` — `TINT_STEPS`: primary 60, secondary 40, tertiary 20, quaternary 15, solid 100. `tintAt(base, step)` is the one mix primitive.
- `renderer/DesignSystem/Tokens/stack.ts:33` — `caret: 2147483647`, "over every layer, deliberately unbeatable." The field overlay inherits this ladder.
- `main/webGuests.ts` — the guest chokepoint: `app.on('web-contents-created')` filtered to `getType() === 'webview'`, plus `installWebGuests`'s `will-attach-webview` validator and the `did-navigate` → `stampGuestZoom` precedent for re-stamping per-navigation state onto a guest.
- `renderer/MarkdownPM/Tables/widget.css:184` — `.mdpm-tbl-wrap .mdpm-tbl .mdpm-tbl-cell.mdpm-tbl-selected { background: var(--accent-fill) }`, with a stated specificity note (outweighs thead and heading-column fills). `renderer/Tables/Table.css:179-181` — `.data-row.selected` at `var(--state-selected)`.
- `renderer/SurfacePM/ViewTile.tsx:150` — the **only** non-CM contenteditable in the renderer (a tile title under edit). The Range-API branch has exactly one consumer.
- `--highlight` is **taken**: `personalization.ts` maps `highlightColor` → `--highlight`, consumed by `MarkdownPM/Styles.css:273` for the `==highlight==` mark. The selection token family cannot use that name.
- **Live measurement (CDP against the running instance, 08-31-2026).** In a real page editor: computed `line-height` **22.8px**, `font-size` 14.25px, actual line advance (`.cm-line` box, body paragraph) **27.07px**, and a rendered `.mdpm-caret` measured **17.54px** tall. A strictly caret-height per-line pill therefore leaves a **~9.5px gap** between consecutive selected lines.
- **Live probe of `::selection` (CDP, 08-31-2026).** A `::selection { background: rgb(0,255,0) }` rule paints inside a real `<input>` (screenshot-confirmed), and `background: transparent` suppresses it. Both legs of the hide-native mechanism hold. The painted box hugs the glyphs at roughly font-size height — it is the inline box, not the field and not the line box, and no CSS moves it.
- **`::selection` accepts only** `color`, `background-color`, `text-decoration`, `text-shadow`, `-webkit-text-fill-color`, `-webkit-text-stroke-color`, `caret-color`. No `border-radius`, no `padding`, no `height`. The same limit applies to the Custom Highlight API's `::highlight()`.

### Decisions

#### A — Geometry

- **A-1:** [confirmed] **The paint is drawn, not native.** Radius, horizontal padding, and a caret-bound height are each individually impossible through `::selection`; together they force an app-drawn highlight. This is not a preference — it is what the property set allows. The native path survives only as the toggle's fallback (D-1).
- **A-2:** [confirmed] **Caret-bound means the envelope, not the per-line box.** A selection spanning lines `a..b` clamps the **first line's top** and the **last line's bottom** to the caret's own top and bottom; interior seams meet at the midpoint of the leading so consecutive lines tile with zero gap. A single-line selection is then exactly caret-height, and a multi-line one is caret-bound at its outer boundary. Forced by the measured 17.54 / 27.07 split — per-line caret-height pills would read as venetian blinds.
- **A-3:** [confirmed] **The radius follows the same rule.** Rounded on the envelope's outer corners, square at the seams, so a multi-line selection reads as one ribbon rather than a stack of pills. One rule governs height and radius together, which is what keeps them a single token family instead of two knobs that can disagree.
- **A-4:** [confirmed] **Padding is horizontal only.** The pill bleeds left and right past the selected glyphs; it never grows vertically, because vertical padding would both break the caret-height match and re-open the seams A-2 closes. The radius/padding ratio is a `KNOB` in the sheet — Nathan's to tune, not to be iterated on his behalf.
- **A-5:** The CM height source is `caret.ts`'s own clamped marker height, reached through a shared helper rather than re-derived — the two paints cannot drift if neither owns a second copy of the number.

#### B — Surfaces & Reach

- **B-1:** [confirmed] **The reach is closed, and it is the caret's reach.** `styles.css:35-43` makes `body` unselectable and re-enables only `input` / `textarea` / `[contenteditable]`. "Everywhere a user can highlight" is therefore not the DOM — it is exactly the surfaces Carets.css already enumerates, plus webview guests. The highlight mounts selector-for-selector against the caret's lists.
- **B-2:** [confirmed] **CM surfaces take a `layer()` beside `caret.ts`**, seated `above: false` so it paints behind the glyphs. Markers come from `RectangleMarker.forRange` over `view.visibleRanges` only, keeping the work viewport-bounded — a document-level `selectionchange` + `getClientRects()` overlay is rejected outright as unbounded on ⌘A.
- **B-3:** [confirmed] **`drawSelection` is rejected**, on the grounds `caret.ts:2` already states: it is an all-or-nothing takeover, and `readOnlySelection.test.tsx` pins behavior that depends on native selection remaining in force.
- **B-4:** [confirmed] **Native fields extend the existing mirror.** `nativeCaret.ts` already lays out an identical mirror and splits it with a span; wrapping the *selected substring* instead yields the selection rects. Same file, same rAF coalescing, same `TEXT_TYPES` and `password` exclusion. It must also **hide the caret bar while the selection is non-empty** — today the bar would sit at `selectionStart` in the middle of a selection.
- **B-4a:** [confirmed] **The field pill paints BEHIND the field's text**, resolving F-1 (Nathan, 08-31-2026). Achievable because every text `<input>` in Pommora already paints on a transparent background — `fields.css.ts` `base` (the in-place rename reset) and `search` are `background: 'transparent'`, `draftInput` is `'none'`; only the `field` **box** carries `fill.quaternary`, and that is the wrapper, not the `<input>` inside it. The pill is therefore inserted as a **sibling of the field inside the field's own parent**, positioned against the nearest positioned ancestor and z-ordered below the input — it shows through the transparent background and the glyphs paint over it. No blend-mode, no reduced tint, no perceptual compromise: the field selection and the editor selection use the same token at the same strength.
  - **This is a second placement strategy, not the caret's.** `.mdpm-caret-overlay` is body-level `position: fixed` at `--z-caret` (max, "deliberately unbeatable"); the pill cannot be, because behind-everything and behind-the-field are different seats. `nativeCaret.ts` grows both.
  - **Bonus correctness:** parent-seated means the pill clips with the field, so a horizontally scrolled input cannot bleed its selection outside the field box — which body-level fixed positioning does not give the caret today.
  - **The dependency is load-bearing and must be pinned:** give any text `<input>` an opaque background and its pill disappears behind it. `fields.css.ts`'s transparent `base` is the contract. Its own comment currently ends "...and leaves the selection to the native highlight" — a claim this work makes false, and which the doc sweep retires.
- **B-5:** [confirmed] **The one non-CM contenteditable** (`ViewTile.tsx:150`) uses the real Range API directly — no mirror, one consumer.
- **B-6:** [confirmed] **The native paint is hidden by scoped selectors, never `:root`-wide.** `::selection { background: transparent }` is applied to exactly the list Carets.css uses for `caret-color: transparent`. A surface nobody enumerated then degrades to a *native* selection rather than an *invisible* one.
- **B-7:** [confirmed] **Webpages are out of scope — no injection is built** (Nathan, 08-31-2026). A guest is a separate WebContents; host CSS vars do not cross it and only `::selection` reaches it, so radius, padding, and caret-bound height are unreachable there by construction. Rather than ship a visibly lesser version of the identity on the one surface that cannot honor it, webpage embeds keep their ordinary native selection. Nothing is added to `main/webGuests.ts`; no accent re-stamp, no per-navigation hook, no main-side toggle gate. Pommora's selection identity is an **app-surface** identity, stated as such.
- **B-8:** [confirmed] **Structural cell and row selection adopts the same tokens.** `.mdpm-tbl-cell.mdpm-tbl-selected` and `.data-row.selected` re-point at the selection token and radius so a swept cell reads as the same identity as swept text. Scoped to those selectors — **not** by re-pointing `--state-selected` itself, which has eight other consumers (`tile-surface.css`, `ActionBand.css.ts`, `GroupBand.css`, the showcase) that must not move. Text selection *inside* a cell is already native and arrives free through B-2.

#### C — Tokens & Naming

- **C-1:** [confirmed] The token family is `--text-selection` and the sheet is `renderer/text-selection.css`, at the renderer root beside `Carets.css` and `styles.css`. The sheet follows the token so the family reads under one word (Nathan, 08-31-2026 — the spec's `text-highlight.css` retired).
- **C-2:** [confirmed] **Scoped to the token family, not the sheet.** `--highlight` is unavailable — it belongs to the `==highlight==` mark (`highlightColor` → `MarkdownPM/Styles.css:273`). Naming is `selection`, never `highlight`, everywhere in the token family, to keep the two legible against each other.
- **C-3:** The focused fill is the accent at `--tint-secondary` (40%), through `tintAt`, matching `--accent-stroke`'s existing recipe rather than minting a parallel one.

#### D — The Toggle

- **D-1:** [confirmed] **`Use Native Highlighting`, Settings › Interface, default off** — off meaning Pommora paints. Stored as `nativeHighlight?: boolean` on `Personalization` (nexus-wide, synced in `settings.json`), because it is an accent-derived look belonging with `accent` / `connectionColor` / `checkboxColor`, not a per-machine system behavior like `nativeMenus`.
- **D-2:** [confirmed] The wiring is **one `ROOT_CLASSES` row** (`nativeHighlight: 'native-highlight'`) plus one `FRAMES` row. The gate is pure CSS — `:root:not(.native-highlight)` guards the drawn paint and the `::selection` suppression together — so flipping it needs no editor reconfigure, no remount, and no reload. The gate is CSS alone, with nothing outside the host document to keep in step — B-7's scope-out is what makes that true.

#### E — States

- **E-1:** [confirmed] **Unfocused selection paints `--fill-tertiary`.** A token swap, not an opacity multiplier — the selection stays visible when focus moves to a toolbar or menu, so select-then-act never looks like the selection was lost, and the unfocused state is a real token rather than a derived dimming of the focused one.
- **E-2:** The caret and the selection are mutually exclusive within one surface: a non-empty selection hides the caret. **Both halves are work.** `caret.ts` today does the opposite — `const cursor = r.empty ? r : EditorSelection.cursor(r.head, r.assoc)` converts a non-empty range into a cursor at `head` and draws a caret there, mid-selection — so the CM half needs the same skip B-4 adds to the native-field half.

#### F — Settled

All three open calls were answered 08-31-2026 and fold into the decisions above: the field pill paints behind the text (B-4a), webpages are out of scope (B-7), and the sheet follows the token to `text-selection.css` (C-1). Nothing is outstanding; the plan can be written against this log.
