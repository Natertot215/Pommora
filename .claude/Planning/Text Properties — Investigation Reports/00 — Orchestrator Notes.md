#### The Cascade Question

Treating a Text value as a small body means running `rewriteConnections` or `rewriteHeadingConnections` over the value where today the cascade patches whole values.

- **Registry in hand:** Every cascade path reads the registry (`cascade.ts:192-195`, `:93`; `spend.ts:257`; `restoreScrub.ts:35`), and the rename cascade already builds `names = byFoldedName(defs)` (`:193`), so a key's definition and type are one lookup away; today it uses the map only to drop unregistered keys (`:194-195`) (B).
- **The primitive is ready:** `rewrite(body, own)` is a pure string-to-string function (`cascade.ts:179-191`; `rewrite.ts:31-60, 65-111`), rebuilding `codeMask` between passes (`rewrite.ts:42-43, 49-50`). `own` is `titleFromPath(file)` (`cascade.ts:212`), which a value on the same page would share, so a value's bare `[[#Heading]]` names its own page. The patch shape `Record<string, string>` carries a rewritten value unchanged (`rewrite.ts:118`; `pageFile.ts:122-127`); the Space arm's `moved(registered(raw))` reaches both the gate and the write, and the held tree already carries a Space's Text values (`cascade.ts:53-56, 196-203`; `spaceSidecar.ts:65-86`) (B, G).
- **The index gap:** Relation rows come from `linksIn` over the body and `frontmatterMentions` over whole values (`indexSeed.ts:61-67`); a sentence link produces neither, so a ready index never names the file (`cascade.ts:172-175`). The seed takes no registry (`indexSeed.ts:46`), re-indexes on mtime and size (`:217-225`), and resets only on `INDEX_GENERATION` (`ddl.ts:3, 80-91`), so a type-gated value scan would leave stale rows after a type change until each page is rewritten. - **The heading-rename gap:** `queryHeadingMentions` has no corpus fallback (`cascade.ts:175`; `fileEvents.ts:296-307`), so a heading rename never reaches a value under either index condition (B).
- **Double handling:** If a body rewriter ran over Text values while the type-agnostic whole-value patch kept running, a value that is exactly one link matches both, and the two writers disagree: `connectionText` drops an alias folding equal to the target, so `[[Old|New]]` renamed to `New` becomes `[[New]]` through one and `[[New|New]]` through the other (`connections.ts:92` vs `rewrite.ts:40`); `parseConnectionText` trims title, heading, and alias where `rewriteConnections` re-emits them as written (`connections.ts:79-85`). - **Cell-escaped pipes:** `rewriteConnections` re-emits `\|` (`rewrite.ts:25-26, 38`), a GFM table convention with no meaning in a yaml value (G).

#### Questions For Nathan
