### Agenda De-Scaffolding Report

Agenda has never been re-thought since the Swift build defined it; before the fresh rethink, this report scopes every agenda-related line in `Pommora/src` into three buckets: **(A) plumbing that stays functional whatever agenda becomes**, **(B) code that presumes a shape nobody re-chose** (fields, JSON grammar, suffixes, schemas, defaults), and **(C) Swift-artifact / parity code that is dead by the standing rule** — "if it exists just to conform to a swift-defined shape or compatibility, it is dead." Every claim below was verified against the working tree; the goal is to let the presumed constraints be deleted with exact knowledge of what to keep and what must be rewired first. [[Agenda]] (`Features/Agenda.md`) itself confirms the census: "The file format and the CRUD behind it are written and tested; no production caller reaches the write path" (`Features/Agenda.md:8`).

#### Functional Regardless of Agenda's Final Form

- **Config-sidecar folder discovery.** An agenda singleton is *only* a folder carrying its config sidecar — never a reserved name (`Features/Architecture.md:65`). The skip logic in adoption (`src/main/adopt.ts:101-110`: "Agenda singletons are identified by their config sidecar (never by name) — skip them") and in the tree walk (`src/main/readNexus.ts:479-493`: a folder with `_taskconfig`/`_eventconfig` is never surfaced as a Collection) is sidecar-based discovery — form-independent. Whatever agenda becomes, "a sidecar marks this folder as not-a-Collection" survives. The *pair* of sidecar names it checks is a shape assumption (see next section), but the mechanism is not. Covered by `src/main/adopt.test.ts:82-96` and `src/main/readNexus.test.ts:175-200`.

- **The sidecar filename registry slot.** `SidecarKind` + `SIDECAR_FILENAME` (`src/main/paths.ts:5-19`) — the pattern that a folder kind is declared by one well-known JSON filename holds for any agenda form; only the two specific entries (`taskConfig`, `eventConfig`) encode the current split.

- **Generic file enumeration.** `listFilesRecursive` and `listFilesBySuffix` (`src/main/io/walk.ts:30-58`) are suffix-agnostic walkers; agenda is one caller among several (`_space.json` sweeps use the same helpers). Nothing agenda-shaped lives in them.

- **Context tagging over any taggable entity.** `setContextOnPath` (`src/main/crud/contextWrite.ts:218-229`) dispatches by entity form — `.md` → frontmatter merge, agenda file → JSON-root rewrite (`setAgendaContext`, `src/main/crud/contextWrite.ts:177-193`), Space folder → sidecar RMW. The *dispatcher* and the parenthesized-key model are form-independent; the agenda branch is currently reachable only through the wired `setContext` mutate op (`src/main/mutate.ts:550-558`), and no UI today produces an agenda path for it (`MutableKind` excludes task/event — `src/shared/mutate.ts:17`), so the branch is wired but UI-unreachable. Tested at `src/main/crud/contextWrite.test.ts:170-196`.

- **The three-scope title cascade.** Context/Space renames and deletes sweep every root that can carry a context key — `.md` frontmatter, agenda JSON roots, `_space.json` roots (`src/main/crud/contextCascade.ts:70-121`, agenda scope at `:102-104`). The invariant "every context-bearing root gets swept" survives any agenda form; what the sweep uses to *find* agenda roots is the suffix pair (shape-coupled edge, below). This is production code that runs today on every Context/Space rename/delete.

- **NavRef agenda kinds.** `NavRef` includes `'task' | 'event'` as identity-only refs (`src/shared/types.ts:283-285`) — kind + id, no shape. The guards that make stored agenda refs safe are equally form-independent: `liveTarget` returns null for agenda kinds so a stored tab/pin ref never resolves to a broken destination (`src/renderer/src/Tabs/tabsModel.ts:31-40`), `pinTarget` refuses them (`src/renderer/src/store.ts:999-1001`), `addFavorite` refuses them (`src/renderer/src/store.ts:1045-1048`), and `resolveWith` yields null because agenda ids are absent from the tree index (`src/renderer/src/Navigation/navResolve.ts`, tested at `navResolve.test.ts:69-85`, `tabsModel.test.ts:362`). These guards are the correct behavior for *any* not-yet-routable kind.

- **Nav-search extras plumbing.** `splitSearch` routes unresolvable hits into inert `extras` (`src/renderer/src/Navigation/useNavData.ts:23-33`), and `NavList` renders them as non-clickable rows (`src/renderer/src/Navigation/NavList.tsx:204`, `:243-253`). The "listed but inert until routable" pattern is form-independent. The snapshot append itself (`src/renderer/src/Navigation/navSearch.ts:26-36`) consumes only `id` + `title` — form-independent given any snapshot.

- **The sidebar mode slot.** `SidebarMode` includes `'agenda'` (`src/shared/types.ts:45`), the Ribbon carries an agenda key with a literal calendar icon (`src/renderer/src/Sidebar/Ribbon.tsx:9-22`), and `readPersonalization` accepts `'agenda'` as a persisted mode (`src/main/readNexus.ts:84-85`). A sidebar surface for agenda exists whatever agenda becomes. Tested at `src/renderer/src/Sidebar/Ribbon.test.tsx:40-79`.

- **Labels.** `NexusLabels.agendaTask` / `agendaEvent` (`src/shared/types.ts:213-214`), defaults at `src/shared/types.ts:471-472`, parsed from settings at `src/main/readNexus.ts:154-155`. Renameable singular/plural pairs are form-independent. **No renderer consumer exists** — nothing reads `labels.agendaTask` or `labels.agendaEvent` outside the parse and test fixtures (`bandCommits.test.tsx:171-172`, `cellGestures.test.tsx:184-185`); the pairs are carried but unused.

- **Trash + write primitives.** `trashWithTimestamp`, `writeJson`, `readJsonObject`, `serializeOnFile` (`src/main/io/atomicWrite.ts`, `src/main/io/fileLock.ts`) — generic; agenda CRUD is just one caller. Same for the shared name rule `invalidName` (`src/main/crud/util.ts:8-14`, "single source for the rule across page + folder + agenda CRUD") and the generic folder-entity CRUD that would create agenda config folders (`src/main/crud/folderEntity.ts:1-2`).

- **Lazy snapshot invalidation.** The store's agenda snapshot is nulled on load and on every tree push (`src/renderer/src/store.ts:631`, `:794`) and lazily re-warmed while a nav surface is open (`src/renderer/src/Navigation/useNavData.ts:52-56`, `store.ts:1079-1086`) — the "pay only when asked, invalidate on tree change" pattern survives any snapshot payload.

#### Presumed Shape — Locks a Form Nobody Re-Chose

- **The suffix grammar.** `AGENDA_SUFFIX` (`.task.json` / `.event.json`) and `agendaKindOf` (`src/shared/agenda.ts:46-56`) hard-code that agenda items are flat JSON files whose filename suffix is the kind authority and whose basename is the title. Every functional edge above reaches agenda *through this grammar*: the cascade sweep finds agenda roots by suffix (`src/main/crud/contextCascade.ts:16`, `:102`), `setContextOnPath` discriminates by suffix (`src/main/crud/contextWrite.ts:20`, `:225`), and `collectAgenda` filters by suffix (`src/main/agenda/collectAgenda.ts:32-35`). Docs state it as load-bearing (`Features/Architecture.md:67`).

- **The two-singleton layout.** Exactly two agenda kinds, each in its own root-level singleton folder discovered by `_taskconfig.json` / `_eventconfig.json` (`src/main/paths.ts:17-18`; discovery at `src/main/agenda/collectAgenda.ts:26-30`, `src/main/adopt.ts:105-109`, `src/main/readNexus.ts:487-493`). The recorded rationale for two separate singletons is EventKit's API split — "EventKit's reminder and event APIs are separate, so the two kinds stay separate singletons rather than sharing one wrapper folder" (`Features/Agenda.md:12`) — a Swift-world justification for an on-disk layout nobody has re-chosen.

- **The item zod schemas.** `agendaTask` / `agendaEvent` (`src/shared/agenda.ts:24-41`) enumerate the exact field vocabulary — `due_at`/`due_floating`/`due_all_day`/`completed`/`completed_at`/`priority` for tasks; `start_at`/`end_at`/`all_day`/`location`/`alarm_absolute` for events — plus the shared base (`:9-21`). Their only production consumer is the read-only list (`src/main/agenda/collectAgenda.ts:6`, `:46`); their field content is EventKit-mirrored (category C, below), but the schemas as gatekeepers are what the one live surface parses through.

- **The `AgendaEntry` wire type.** `src/shared/types.ts:48-57` — `dueAt` / `startAt` / `endAt` on the IPC reply bake the task-has-due / event-has-span shape into the cross-process contract (`src/shared/bridge.ts:223`), even though the only renderer consumer (`AgendaMode.tsx`) reads just `id`, `title`, `kind`, `icon`.

- **`collectAgendaEntries` itself.** `src/main/agenda/collectAgenda.ts:13-64` — root-level singleton scan, suffix filter, per-kind zod parse, and per-kind field extraction (`due_at` at `:52`, `start_at`/`end_at` at `:57-58`). The whole function is a reader of the presumed shape.

- **The agenda config sidecar schema.** `agendaConfigSidecar` (`src/shared/schemas.ts:69-73`) presumes each kind carries its own inline `property_definitions` — the pre-PropertiesV2 model that Collections already left ("Collections left this path in PropertiesV2 (their defs live in the nexus-wide registry); only Agenda configs still hold inline `property_definitions`" — `src/main/crud/schema.ts:2-3`). Its only code consumer is the dead schema CRUD (`src/main/crud/schema.ts:10`, `:87`); the sidecar *filenames* separately serve discovery, but this zod schema does not.

- **Error codes.** `'invalid-event'` and `'not-agenda'` in the closed `ErrorCode` union (`src/shared/result.ts:12-13`) presume, respectively, that an event requires `start_at`+`end_at` and that "agenda item file" is a suffix-decidable category. Sole consumers: the dead CRUD (`src/main/crud/agendaEntity.ts:50`, `:64`).

- **The per-file-kind adoption gap.** Adoption skips agenda folders wholesale and defers per-file kind assignment to the suffix discriminator (`src/main/adopt.ts:102-104`; `Features/Architecture.md:69`) — a pending design premised on the suffix grammar continuing.

#### Swift-Artifact / Parity — DEAD

- **The EventKit field mirror in `src/shared/agenda.ts`.** The file's own header declares the parity: "Tasks (EKReminder-shaped) + Events (EKEvent-shaped)" (`src/shared/agenda.ts:1`), and the feature doc confirms "each mirroring an EventKit kind" (`Features/Agenda.md:3`). The fields that exist *only* to mirror EKReminder/EKEvent or hold sync state for an unbuilt EventKit bridge (`Features/Agenda.md:38`: "the bridge isn't built"): `recurrence` (`:17`, round-tripped, never edited), `alarm_offsets` (`:18`), `calendar_id` (`:19`), `eventkit_uuid` (`:20`), `alarm_absolute` (`:40`), `due_floating`/`due_all_day` (`:26-27`), `priority` (`:31` — EKReminder's priority scale). **Dependency:** none functional — `collectAgenda` reads only `id`/`icon`/`due_at`/`start_at`/`end_at`; the loose-object parse means removing fields from the schema breaks nothing that reads them.

- **The dead `properties` record field.** `agendaBase.properties: z.record(...)` (`src/shared/agenda.ts:13`) — zero readers, zero writers. Even the dead CRUD's own `updateAgendaProperty` writes values under the property's *name key* at the JSON root (`src/main/crud/agendaEntity.ts:113-117`), never into a `properties` record; `collectAgenda` never touches it. A Swift-era layout remnant with no consumer of any kind. **Dependency:** none.

- **`src/main/crud/agendaEntity.ts` — the whole file (120 lines).** Full create/rename/delete/update/set-property CRUD written to the Swift JSON grammar, with EventKit defaults baked into create (`priority: 0`, `due_floating: false`, `alarm_offsets: []`, `alarm_absolute: []` — `:31-48`) and the event start/end requirement (`:49-51`). **Zero production consumers** — verified: the only importers are `agendaEntity.test.ts`, `agendaSchema.test.ts`, and `contextWrite.test.ts:14`; no mutate op, no IPC channel reaches it (`Features/Agenda.md:8`, `:34`: "the mutate ops and IPC that would reach the existing CRUD are unbuilt"). **Dependency before deletion:** `contextWrite.test.ts:170-196` uses `updateAgendaItem`/`updateAgendaProperty` as concurrent-writer harnesses for the agenda file-lock tests — those tests must be rewritten against another RMW writer or deleted with the surface they test.

- **The agenda schema CRUD in `src/main/crud/schema.ts` (everything except `stripPageMember`, ~230 of 249 lines).** `agendaTarget` + `rewriteAgendaMember` (`:68-92`) and the four exported ops (`addAgendaProperty`/`renameAgendaProperty`/`deleteAgendaProperty`/`changeAgendaPropertyType`, `:230-249`) have **zero production consumers** — verified: nothing in `src` imports them; the file's only external import is `stripPageMember` (`src/main/crud/removeProperty.ts:10`, `src/main/crud/deleteProperty.ts:16` — the registry delete fan-out, which is live). The generic `SchemaTarget` core (`:40-226`) has `agendaTarget` as its *only* instantiation, so it is agenda-only by construction — it exists to operate the inline-`property_definitions` model agenda inherited from Swift. **Dependency before deletion:** `stripPageMember` (`:56-66`) must move (its natural home is beside `src/main/crud/pageValue.ts`, whose header already pairs with it); `SchemaTransaction` (`src/main/io/schemaTransaction.ts`) loses its last consumer when the generic core goes — verified sole non-io consumer is `schema.ts`.

- **`agendaConfigSidecar`** (`src/shared/schemas.ts:69-73`) — consumed only by the dead schema CRUD (`src/main/crud/schema.ts:10`, `:87`). Dies with it. The `_taskconfig.json`/`_eventconfig.json` *filenames* in `paths.ts` are separate and stay (discovery).

- **Error codes `'invalid-event'` + `'not-agenda'`** (`src/shared/result.ts:12-13`) — sole consumers are the dead CRUD lines above. Die with it.

- **JSON-mechanics tests.** `src/main/crud/agendaEntity.test.ts` (140 lines) and `src/main/crud/agendaSchema.test.ts` (121 lines) test only dead code; `src/main/agenda/collectAgenda.test.ts` (58 lines) tests the interim read path and lives or dies with it (section below).

#### The Interim Question — RULED

**Nathan's ruling: everything dies; the sidebar's Agenda mode becomes inert.** Steps 1 and 2 below are both authorized; the mode slot, ribbon entry, and label pairs stay (form-independent), rendering the empty state until the fresh agenda fills them. Swift-era agenda folders are a non-concern — any found on a real disk are deleted manually, never tolerated in code.

One agenda surface is live, and it reads the Swift-shaped files end-to-end: `agenda:list` (`src/shared/bridge.ts:223` → handler `src/main/index.ts:496-505` → preload `src/preload/index.ts:134-135`) runs `collectAgendaEntries` over the two singletons and feeds exactly two things — the sidebar's read-only Agenda mode (fetch in `src/renderer/src/Sidebar/Sidebar.tsx:505-521`, display-only rows in `src/renderer/src/Sidebar/AgendaMode.tsx`, styles `Sidebar.css:181-200`) and the nav-search snapshot (`store.ts:1078-1086` → `navSearch.ts:26-36` → inert extras rows). Rows open nothing and search hits are inert ("Agenda navigation isn't wired yet" — `NavList.tsx:246`).

If the shape-bound code (`shared/agenda.ts` item schemas, `collectAgenda.ts`, `AgendaEntry`) is deleted before the fresh agenda lands, what dies visually: the Agenda ribbon mode renders its empty state ("No tasks or events" — or nothing at all if the channel goes too), and agenda titles stop appearing as inert rows in nav search. That is the entire user-visible loss — no tab, pin, favorite, preview, or tree surface ever shows an agenda entity (the guards in section one make stored refs resolve to nothing). Existing `.task.json`/`.event.json` files on disk simply become invisible to the app; the cascade sweep would stop rewriting their context keys (acceptable only if those files are also considered dead data).

#### Deletion Order

**Step 1 — deletable today, zero impact on any running surface:**
1. `src/main/crud/agendaEntity.ts` + `src/main/crud/agendaEntity.test.ts` + `src/main/crud/agendaSchema.test.ts`, and the agenda-lock block of `src/main/crud/contextWrite.test.ts:170-196` (or rewrite its concurrency harness around `setAgendaContext` alone).
2. `src/main/crud/schema.ts` minus `stripPageMember` — relocate `stripPageMember` first (`removeProperty.ts:73` and `deleteProperty.ts:72` are its live callers), then delete `agendaTarget`, `rewriteAgendaMember`, the four exports, and the now-orphaned generic core; `src/main/io/schemaTransaction.ts` goes with it once its last consumer is gone.
3. `agendaConfigSidecar` (`src/shared/schemas.ts:69-73`) — unreferenced after step 2.
4. `'invalid-event'` + `'not-agenda'` (`src/shared/result.ts:12-13`) — unreferenced after step 1.
5. The dead `properties` field (`src/shared/agenda.ts:13`) and the EventKit mirror fields (`:16-20`, `:26-27`, `:31`, `:40`) — the loose parse means the interim list keeps working without them.

**Step 2 — dies with an explicit call on the interim surface:** `src/main/agenda/collectAgenda.ts` + its test, the `agenda:list` channel triple (bridge/handler/preload), `AgendaEntry` (`src/shared/types.ts:48-57`), the store snapshot + `ensureAgendaSnapshot` (`store.ts:1078-1086` and the two invalidations at `:631`/`:794`), the Sidebar fetch + `AgendaMode.tsx` + its test + `Sidebar.css:181-200`, the `navSearch.ts:31-35` append, and the `agendaTask`/`agendaEvent` item schemas in `shared/agenda.ts`. These form one connected component — removing any link dead-codes the rest, so they go together, either now (accepting the visual loss above) or when the fresh agenda replaces them.

**Step 3 — falls out only after step 2:** `AGENDA_SUFFIX` + `agendaKindOf` (`src/shared/agenda.ts:43-56`) lose their last consumers once `collectAgenda` is gone *and* the cascade/context edges are trimmed — the suffix references in `contextCascade.ts:16`/`:102-104` and `contextWrite.ts:20`/`:225` are harmless no-ops on a nexus with no suffix-matching files, but they are the last code asserting the old grammar and should be cut in the same pass. The two config-sidecar entries in `paths.ts:17-18` and the folder skips in `adopt.ts`/`readNexus.ts` stay until the fresh agenda decides its own discovery — deleting them early would let stray Swift-era agenda folders adopt as Collections.

**Never delete:** everything in the first section that isn't agenda-specific — the walk helpers, trash/lock/JSON primitives, `folderEntity`, `invalidName`, the NavRef guard pattern, the extras rendering, the sidebar mode slot, the labels slots, and the context-tagging dispatcher pattern.
