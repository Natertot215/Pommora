## Data-Layer Lessons

Traps proven in the main process's storage and index code — read before writing anything that touches `nexus.db` or a nexus-wide sweep.

- **SQLite's character functions and JS `.length` count different things.** `substr`/`length` count code points; `.length` counts UTF-16 units, so an offset computed in JS and applied in SQL walks one short per astral character (an emoji in a folder name swallowed a path separator). Compute offsets on one side only — `substr(path, length(?) + 1)` with the same parameter, never `oldDir.length + 1` handed across.
- **"No result" and "no index" are different answers and must stay different types.** A derived store's query answers `null` when the store cannot answer — no handle, tables that never landed, a seed that has not finished — and an empty array only when it genuinely searched. Freshly created tables are empty, which is why readiness is stamped by the seed rather than inferred from the tables existing; every `null` caller falls back to its full scan.
- **A long-running seed must pin the handle it started against.** Module-level `sessionDb()` resolves live, so a loop that awaits per file can wake up holding a different nexus's database; bail when the identity moved rather than pouring one corpus's rows into another's store — and prune from a pre-pass snapshot, never from "everything not seen this pass," or rows born mid-pass get reaped.
- **A reach-scoped negative control can expose the pen itself.** Instrumenting exactly which files a cascade opens surfaced a latent writer bug (a body-only merge inventing `null` frontmatter on frontmatter-less files) that every ordinary green run had sailed past — when a control fails for a reason other than the guard, chase the pen before loosening the assertion.
- **No write Pommora makes is visible to its own watcher.** `atomicWriteBinary` and `atomicWriteFile` call `recordWrite`, and `isRecentWrite` drops the echo before `settle` runs — so any derived state a write moves must be updated by the writer itself, on the writer's own channel. A feature that builds the external-change machinery and never asks what happens when the app is the writer ships green with three silent defects: the derived listing goes stale, the re-arm never fires, and the guard that depends on both deletes the wrong thing. The test shape that catches it drives the real path and asserts against the state the app is HOLDING, never against one rebuilt from disk.
- **A filename is a nexus-wide key, so a collision check scoped to one folder is not a collision check.** Resolution by basename means a name held anywhere under a root answers for all of them; deduplicating against the destination directory alone lands a second file that makes both permanently ambiguous. Ask the map, not the folder.
- **A migration that walks the directory carries the graveyard with it.** Deleting an entity leaves its asset folder behind, so a directory-driven copy moves long-dead entities' leftovers into wherever the user pointed. Walk the STORES; sweep the directory only once every reference has moved, and hold the sweep entirely if any reference was skipped — the file a skipped reference still names is the only copy of it.
- **A path-segment normalizer that drops empty segments does not drop `..`.** Splitting a relative path and filtering the blanks reads like sanitizing, and every ordinary input comes out looking sanitized; `..` survives it, and the `join` downstream collapses it past the root. A renderer-supplied subfolder reached the nexus root at `'../..'` and escaped the nexus entirely at `'../../..'`, with `mkdir -p` creating whatever it needed on the way. **Containment is a predicate that must refuse `..`, `.` and the empty segment by name**, and it belongs at the write seam rather than at the channel, so every caller inherits it instead of the one that was audited. A comment crediting the normalizer for the empty-segment case is what made the gap invisible — it described what the function did and was read as describing what it protected.
