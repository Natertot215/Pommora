## Data-Layer Lessons

Traps proven in the main process's storage and index code — read before writing anything that touches `nexus.db` or a nexus-wide sweep.

- **SQLite's character functions and JS `.length` count different things.** `substr`/`length` count code points; `.length` counts UTF-16 units, so an offset computed in JS and applied in SQL walks one short per astral character (an emoji in a folder name swallowed a path separator). Compute offsets on one side only — `substr(path, length(?) + 1)` with the same parameter, never `oldDir.length + 1` handed across.
- **"No result" and "no index" are different answers and must stay different types.** A derived store's query answers `null` when the store cannot answer — no handle, tables that never landed, a seed that has not finished — and an empty array only when it genuinely searched. Freshly created tables are empty, which is why readiness is stamped by the seed rather than inferred from the tables existing; every `null` caller falls back to its full scan.
- **A long-running seed must pin the handle it started against.** Module-level `sessionDb()` resolves live, so a loop that awaits per file can wake up holding a different nexus's database; bail when the identity moved rather than pouring one corpus's rows into another's store — and prune from a pre-pass snapshot, never from "everything not seen this pass," or rows born mid-pass get reaped.
- **A reach-scoped negative control can expose the pen itself.** Instrumenting exactly which files a cascade opens surfaced a latent writer bug (a body-only merge inventing `null` frontmatter on frontmatter-less files) that every ordinary green run had sailed past — when a control fails for a reason other than the guard, chase the pen before loosening the assertion.
