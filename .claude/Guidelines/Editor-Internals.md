## Editor Internals

Hard-won constraints for working inside MarkdownPM. Each entry is a rule the editor's correctness depends on; verify against these before changing the layer they name.

- **Fence pairing is one shared pass.** The fence grammar and its pairing live in the shared code module beside the mask the write side reads; every layer consumes that pass rather than pairing fences itself. A layer pairing for itself eventually under-claims a block, and an under-claimed block is one whose `[[Title]]` a rename will rewrite — a file edited inside its own code sample. Two divergences from the reference parser are intentional: the info-string capture stays unanchored at line-end (or CRLF documents lose every fence), and a backtick fence whose info string holds a backtick is prose.
- **Emphasis markers are located by geometry, not width-subtraction** — per side, take the tighter of the content bounds; naive `start + width` mislocates whenever an inner span abuts the delimiter run. Re-validate against the parser's offset semantics if the parser is swapped.
- **Block constructs confirm by parsing a single line in isolation** — a bare `---` is always a thematic break. Setext H2 was removed; a setext-underline guard must not be reintroduced.
- **`WidgetType.ignoreEvent` defaults to `true`** — an interactive glyph widget needs an explicit `ignoreEvent → false` or pointerdown never reaches its handler.
- **All offsets are character offsets (UTF-16), never bytes** — micromark reports char offsets; still guard astral-plane characters at parser boundaries.
- **Hot-path reads share one per-doc-version derivation** — the doc string, the one whole-document scan, and the caret-free per-line intents compute once per document version; a caret move re-derives only the line the caret sits on. Inline tokenizing scopes to the visible ranges, cached by doc version and span set. Don't add a per-caret or per-move whole-doc read.
- **A parse given a fragment answers about the fragment.** The editor tokenizes a slice, so anything whose meaning depends on the lines above it — fence parity, list indentation — comes out wrong unless the slice opens somewhere unambiguous. Every slice that reaches the parser must open on a line whose block context is self-evident.
- **A block widget must answer how tall to assume it is, on every edit inside its range.** Answering "unknown" means one line, so the document's height lies until the next measure — the cause of a block widget's surface jerking the scroll while it is typed in. CM6 hands the node to `destroy(dom)` so per-node resources can be released, and calls it only when the node is truly dropped; a widget replaced over reused DOM is never destroyed.
- **A table cell is not an editor until it is entered.** A resting cell renders as plain spans with no `EditorView` at all, so anything a link, a gesture or a menu does in the body has to be given to the resting cell separately. Settling is the matching trap: the table redraws when a cell editor demotes, and a cell never entered has none to demote, so a write that reaches a resting cell must settle the table itself or the edit lands in the document while the widget keeps drawing what was there before.
- **Box constructs float with an outer gap, never a line margin** — CM6 line margins break caret mapping. Each box paints its fill as an inset `::after` and pads its edge lines by its own gap knob; a box nested in a box drops its gap.
- **A list line wraps only inside its content span** — the line is `white-space: pre` and the item's content wears the one wrapping region; the marker zone is saturated with soft-wrap opportunities that would drop a long word below its glyph. Re-test a single-long-word item at narrow width before touching either.
- **Display math is a block to every layer that can move or mark it** — a pair of lone `$$` lines under fence-style pairing, never the token layer's lazy span regex. One derivation (the shared document scan) feeds the block resolver, the list gesture, and the decoration pass; indented math rides its list item whole.
- **The embed claim has one owner** — the resolved, first-per-title claim set is read by the tile field, token suppression, boundary guards, grip-menu exclusions, and the autocomplete pool; don't add a second predicate. Protect embed edits at the transaction layer, never by chasing motion commands.
- **A grip's right-press is defaulted away** exactly as the drag gestures default the left — preventing the context menu comes too late to stop the browser seating a caret. The gutter's hover flag and the grip menu's hit-test read one grip-bearing line-class list; keep it that way.
- **The fold and the outline read one fence-aware heading scan** and disagree on purpose — a fold section is dropped when nothing sits beneath its heading; the outline keeps it. The editor publishes a reveal seam beside its fold toggle: scroll to an offset, opening every collapsed section hiding it.
- **The heading scan, block resolver, and decoration pass agree that a closed top-level fence owns its bytes** — a `>` or `[!callout]` line inside one is code text; a quoted fence keeps its box because the `>` is real there.
