## Editor Internals

Hard-won constraints for working inside MarkdownPM. Each entry is a rule the editor's correctness depends on; verify against these before changing the layer they name.

- **Fence pairing is one shared pass.** The fence grammar and its pairing live in the shared code module beside the mask the write side reads; every layer consumes that pass rather than pairing fences itself. A layer pairing for itself eventually under-claims a block, and an under-claimed block is one whose `[[Title]]` a rename will rewrite — a file edited inside its own code sample. Three divergences from the reference parser are intentional: the info-string capture stays unanchored at line-end (or CRLF documents lose every fence), a backtick fence whose info string holds a backtick is prose, and a fence nothing closes opens no code block rather than one running to the end — the parser is handed that reading too, its marker masked. Code colors read the same blocks: each block the scan found is parsed alone with its language, and the page's Markdown language paints nothing.
- **Emphasis markers are located by geometry, not width-subtraction** — per side, take the tighter of the content bounds; naive `start + width` mislocates whenever an inner span abuts the delimiter run. Re-validate against the parser's offset semantics if the parser is swapped.
- **Block constructs confirm by parsing a single line in isolation** — a bare `---` is always a thematic break. Setext H2 was removed; a setext-underline guard must not be reintroduced.
- **`WidgetType.ignoreEvent` defaults to `true`** — an interactive glyph widget needs an explicit `ignoreEvent → false` or pointerdown never reaches its handler.
- **All offsets are character offsets (UTF-16), never bytes** — micromark reports char offsets; still guard astral-plane characters at parser boundaries.
- **Hot-path reads step from the version before.** The doc string is joined once per document version, and the scan, the caret-free per-line intents, and the atomic set are each held once per version and stepped by every transaction from the version it started from: `rescan` re-scans only the lines between the quiet lines around the edit, the intents re-derive only those lines and the citation lines whose chrome moved, and the atomic set is mapped and re-reads the same lines. The one `transactionExtender` (`stepDocs`) does it before any field, facet, or plugin reads the new version, and a transaction filter that reads the new document takes `docScan.after(tr)`. A caret move re-derives only the line the caret sits on. A check that confirms a line, cell, or table with a parse is remembered by its text through `perText`, which copies each key because a split line is a view that would keep its whole document alive; the viewport's token chunks and code-block trees are remembered per view, by text, for as long as they stay on screen. Don't add a per-caret or per-move whole-doc read, and don't derive a version from nothing where the one before it is held.
- **A parse given a fragment answers about the fragment.** The editor tokenizes its viewport in chunks, so anything whose meaning depends on the lines above — fence parity, list indentation, an open HTML block, a paragraph's lazy continuation — comes out wrong unless each chunk opens where the parser holds no state. A chunk opens only at a `cutAt` line: a quiet line (nothing multi-line is open above it) that is flush left and non-blank and, below a list item, interrupts the item's paragraph. Fenced lines hold no inline tokens, so a chunk never opens on one. Where no cut line sits within `CHUNK_REACH` lines of the screen, the chunk starts at the screen's edge — at the opener of a math block the edge falls in, or at the flush line that owns an indented run — and ends at it, stretching to the end of a math block and stopping short of a fence. Two constructs still read differently inside a chunk, and each is pinned: a reference whose definition sits in another chunk, and a fence the scan and the parser pair differently.
- **A block widget must answer how tall to assume it is, on every edit inside its range.** Answering "unknown" means one line, so the document's height lies until the next measure — the cause of a block widget's surface jerking the scroll while it is typed in.
- **A React widget's first render has to land before CodeMirror measures it.** An asynchronous root leaves CM measuring an empty node, which collapses the widget, corrects the scroll, and churns the viewport; a `flushSync` inside `toDOM` drains other roots' effects into CM's update, where a dispatch throws. `ReactWidget` flushes the first render in a microtask, after the update and before paint, and a table reserves its carried height until then.
- **Whatever answers the height question answers for the FULL vertical footprint, and a vertical margin is the part it forgets.** A block widget is measured by its own element's box, which excludes margin; an inline widget filling a line reports through `estimatedHeight`, and its margin does not collapse out of the line because CM parks a `cm-widgetBuffer` on either side of the replace. Either way the height model runs short by the gap for every widget of that kind on the page, and below them the caret seats on whichever line the accumulated error points at — a defect that reads as the construct underneath being broken rather than as anything about the widget. Spend the gap as padding where the element carries no border or fill; where it cannot, add it to the height reported. CM6 hands the node to `destroy(dom)` so per-node resources can be released, and calls it only when the node is truly dropped; a widget replaced over reused DOM is never destroyed.
- **A widget identity change re-seats the span.** When a widget's `eq` goes false, CM's sync detaches the node and re-inserts it — same reference, but every CSS transition on it cancels (the change lands as a snap) and a webview inside it loses its guest (the site reloads). Anything animated or guest-bearing flows around widget identity: update the field's value without touching `eq`'s inputs, then write the rendered DOM directly, as the embed tiles' Scale does through `refreshTileZooms`.
- **A table cell is not an editor until it is entered.** A resting cell renders as plain spans with no `EditorView` at all, so anything a link, a gesture or a menu does in the body has to be given to the resting cell separately. Settling is the matching trap: the table redraws when a cell editor demotes, and a cell never entered has none to demote, so a write that reaches a resting cell must settle the table itself or the edit lands in the document while the widget keeps drawing what was there before.
- **A cell's document model is page-shaped, whatever the cell draws.** `docScan` and `blockStarts` read one vocabulary, so a fence, a quote, display math or a citation row inside a table cell registers in the model even though cell scope renders every one of them as literal text. A cell-side reader of `fences`, `quotes`, `maths`, `citations` or a block kind is therefore answering a question about a construct the surface never shows: the effects reach as far as a refused marker collapse and a list that draws without its grip. The same holds for `Engine/listDragModel.ts`, whose whole module reads the prefixed marker grammar. The scope belongs to the reader — `smartBackspace` and the intent builders take it — and any new cell-side transform that consults the scan or that grammar needs the same.

- **A box line's two pseudo-elements are both already spent** — `::before` carries the border or the quote bar, `::after` carries the fill, the drag grip, and a nested construct's own clamp. A fifth box construct can join the shared base and state its measures under the `--box-*` names; one that must nest *inside* another box has no layer left to paint with and needs a different mechanism. Every `:is()` argument in the base is a single class on purpose: the selector takes its most specific argument's weight, and a two-class argument lifts the whole rule over the first/last rules meant to refine it.
- **Box constructs float with an outer gap, never a line margin** — CM6 line margins break caret mapping. Each box paints its fill as an inset `::after` and pads its edge lines by its own gap knob; a box nested in a box drops its gap.
- **A list line wraps only inside its content span** — the line is `white-space: pre` and the item's content wears the one wrapping region; the marker zone is saturated with soft-wrap opportunities that would drop a long word below its glyph. Re-test a single-long-word item at narrow width before touching either.
- **Display math is a block to every layer that can move or mark it** — a pair of lone `$$` lines under fence-style pairing, never the token layer's lazy span regex. One derivation (the shared document scan) feeds the block resolver, the list gesture, and the decoration pass; indented math rides its list item whole.
- **The embed claim has one owner** — the resolved, first-per-title claim set is read by the tile field, token suppression, boundary guards, grip-menu exclusions, and the autocomplete pool; don't add a second predicate. Protect embed edits at the transaction layer, never by chasing motion commands.
- **A grip's right-press is defaulted away** exactly as the drag gestures default the left — preventing the context menu comes too late to stop the browser seating a caret. The gutter's hover flag and the grip menu's hit-test read one grip-bearing line-class list; keep it that way.
- **The fold and the outline read one fence-aware heading scan** and disagree on purpose — a fold section is dropped when nothing sits beneath its heading; the outline keeps it. `docOutline`, `docHeadingKeys`, and `docSectionHeadings` derive from that one scan per document version beside them. The editor publishes a reveal seam beside its fold toggle: scroll to an offset, opening every collapsed section hiding it.
- **The heading scan, block resolver, and decoration pass agree that a top-level fence owns its bytes** — a `>` or `[!callout]` line inside one is code text; a quoted fence keeps its box because the `>` is real there.
- **The citations section is the document's TAIL, and its failure is total.** A `[^label]: text` run counts only while it reaches the document's end, so one non-blank line left standing after it does not corrupt one citation — every citation in the section becomes literal text at once. Anything that writes at or near the document's end asks the transaction guard first, and anything that writes a citation seats it at or after the marker it belongs to: a caret on the empty last line of a document ending in a newline sits past the body's last content, and a citation seated behind it lands above its own marker.
- **A fold entry maps its start forward and its end backward.** An edit that GROWS a folded region therefore leaves the new lines standing outside the collapsed widget, visible on a page whose section is meant to be hidden — no offset discipline avoids it, because the edit legitimately owns that offset. A region rewritten under a fold drops the fold across the edit and re-takes it after, which also re-captures the clone the reveal animates from. The heading drag does this for the same reason.
- **A repair that MOVES text is two edits, not one.** A transaction-filter verdict that relocates has to carry the range it moves text out of as well as the destination; carrying only the destination leaves the original standing and writes a copy elsewhere. Where the two would overlap, the change goes through unrepaired — the guard exists to stop text being stranded, not to stop it being removed. Its destination is read off the line it lands on rather than assumed: the line above the citations section is the blank the section floats on only in a file this editor wrote, and text seated at the start of a line that holds prose lands above that paragraph instead of after it.
- **A leaf that both the editor and a React surface call must import nothing from either.** `Core/Interface/Glance/GlancePane.tsx` reaches into MarkdownPM for the fold and the page tile, and MarkdownPM's pointer path and table cells both have to arm and close the pane: the cycle resolved at runtime by leaving one side's bindings uninitialized, and the first mount to render a table threw inside `TableView`. The imperative seam lives in its own leaf (`Core/Interface/Glance/glanceAction.ts`), imports nothing, and the component claims its presenter slot at mount.
- **A predicate answered on every caret move reads the cached scan, never the document.** `codeAt` is the one answer to whether an offset is code (its line is fenced, or it sits inside an inline span), and `inCodeAt` and `inCalloutAt` are the readers the input transforms take over the scan. `codeMask(text)` answers the same query for a string no scan holds. A transform that needs to know more than its own line takes the scan, not the string.
- **The drawn chrome is windowed to the viewport; the atomic set is not.** The assembly copies cached intents for the viewport's lines only — safe without any margin, because every `first`/`last` flag was decided by the whole-document derivation before the viewport was consulted, so a window only ever selects among already-correct answers. `atomicRanges` is the exception and must stay whole-document: it decides where a caret or a selection endpoint may land, and a motion resolved against a slot the viewport hasn't reached seats the caret inside a marker nothing on screen stands for. Its per-version set is mapped from the last one's and re-reads only the lines the intents re-derived; the caret's own line, where the viewport holds it, drops through a range-bounded filter, never a rebuild.
- **Rails are emitted after every line intent, never interleaved with them.** They anchor at the same offset as their line's own classes, and emission order is what stacks those classes — the whole-document reference emits rails last, and the windowed assembly matches it deliberately.
- **A line's start is `lineStartAt`, never a hand-rolled `lastIndexOf('\n', pos - 1)`.** JavaScript clamps a negative `fromIndex` to 0, so at position 0 of a document that opens with a newline the search finds that newline and answers line two; every transform that trusted it then acted one line down or dispatched an inverted range. `Input/edits.ts` carries the guard once; a sibling that spells the search itself carries the defect again.
- **A pane held through its exit animation keeps the closed render's handlers.** `PickerMenu` leaves its children mounted for the exit, so a row's `onMouseDown` from the last open render stays clickable with the state that render captured. A pick reads the live ctl's `open` before it acts, and never a value the closure captured; the block menu and the `[[` pane both refuse through `useMenuCtl` for this reason.
- **A block-menu row runs the same transform the context menu does, and the transform decides where the caret rests.** A divider seats it on the line below the rule, a table on the line below the table, a quote after `> ` on a single blank line; the pane removes only the typed `/query`, outside history, so the transform's own dispatch is the one undo step for every row.
- **A landing is one changes-only transaction carrying `syncLanding`.** `verdictFilter` passes it through and re-carries the annotation; `Transaction.addToHistory.of(false)` keeps it out of undo; its changes are the diff between the buffer and the merged text, and no selection is given, so the default mapping keeps the caret where the edit left it.
- **Every stepped derivation answers to its full derivation.** `rescan` must equal `scanDoc`, `stepLineIntents` must equal `docLineIntents`, and the stepped atomic set must equal a fresh one; the seeded properties in `Engine/docScan.test.ts` and `docCache.test.ts` are the specification. An intent carries document positions only in `from` and `to`, which is all a carried line has shifted. A construct the scan learns joins the generator's alphabet in the same change, and a resync rule widens only with the property run against it: letting arrow items resync broke table headers, because CommonMark reads `→ a | b` above a delimiter row as one.
